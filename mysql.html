What is MySQL? Explain the MySQL architecture

MySQL Basics 7 min read Difficulty: Beginner 1 of 55
Definition

MySQL is an open-source relational database management system, now owned by Oracle. It stores data in tables, is queried with SQL, and is one of the most widely used databases behind web and business applications.

Its defining design feature is the pluggable storage engine architecture: one common SQL layer (parsing, optimisation, execution) sits on top of interchangeable engines that store the data. InnoDB has been the default engine since MySQL 5.5.

Why it matters: For a data engineer, MySQL is most often a source system: the OLTP database of an application that you extract from (full loads, incremental loads, or CDC from the binary log).
MySQL 8.0 InnoDB Storage Engine Optimizer Port 3306 Client-Server
How It Works — Step by Step
Step 1 / 8
  1. 1A client (the mysql command line, a Java/Python program, Spark over JDBC) sends a SQL statement over TCP port 3306 or a local socket.
  2. 2The connection layer gives the session a thread, checks user@host and password, and later checks privileges for each table touched.
  3. 3The parser checks syntax and builds a parse tree. Misspelled keywords fail here with ERROR 1064.
  4. 4The optimizer estimates costs and chooses the plan: which index to use, the join order, whether to sort in memory. EXPLAIN shows this decision.
  5. 5The executor runs the plan, asking the storage engine for rows through a common handler API.
  6. 6The storage engine (InnoDB by default) actually stores and fetches rows. It keeps hot pages in the buffer pool (memory) and uses redo/undo logs for transactions.
  7. 7Data finally lives on disk as InnoDB tablespace files (.ibd). Changes are also written to the binary log, used for replication and CDC.
  8. 8The result set travels back up the same path to the client.
Detailed Explanation

Because the engine is chosen per table, features such as transactions, row locking and foreign keys are engine features, not MySQL-wide features. That is why the InnoDB vs MyISAM question is so common.

Cross Questions
Is MySQL the same as MariaDB?
MariaDB is a fork of MySQL created in 2009 by MySQL's original developers after Oracle acquired it. Basic SQL is the same, but they have diverged: for example the ->> JSON operator and EXPLAIN ANALYZE are MySQL 8 syntax, while MariaDB has its own equivalents.
What is the default port of MySQL?
3306. MySQL X Protocol (document store) uses 33060.
What is the difference between MySQL and SQL?
SQL is the query language (a standard). MySQL is a database product that implements SQL, plus its own extensions such as LIMIT, ON DUPLICATE KEY UPDATE and GROUP_CONCAT.

What is the difference between InnoDB and MyISAM?

Definition

InnoDB is MySQL's default, transactional storage engine: it supports ACID transactions, row-level locking, foreign keys and crash recovery.

MyISAM is the older, non-transactional engine with table-level locking. It is rarely used for new tables today.

Interview Tip

A short answer that scores well: "InnoDB is the default and should be used for almost everything because it gives transactions, row locks, foreign keys and crash safety. MyISAM is legacy: no transactions and table-level locks, so it only made sense for read-mostly tables in old versions."

Cross Questions
How do you change a table's engine?
ALTER TABLE t ENGINE = InnoDB; It rebuilds the table, so run it in a maintenance window for big tables.
Which other engines exist?
MEMORY (data in RAM, lost on restart), CSV (stores rows as a CSV file), ARCHIVE (compressed, insert-only), BLACKHOLE (discards writes but still logs them for replication).

Cross Questions
What does INT(11) mean?
Only a display width hint for ZEROFILL, not a size limit. INT is always 4 bytes. MySQL 8.0.17+ deprecates the width.
What is the difference between VARCHAR and TEXT?
VARCHAR can have a default value and be fully indexed, and is stored inline. TEXT has no default (before 8.0.13), needs a prefix length to be indexed, and large values may be stored off-page.
What is AUTO_INCREMENT?
A column attribute that generates the next integer for each new row, usually for surrogate primary keys. LAST_INSERT_ID() returns the value generated by your own session's last insert.

Cross Questions
Why is TRUNCATE faster than DELETE?
DELETE removes rows one by one, writing undo and binlog entries and updating every index for each row. TRUNCATE just drops and recreates the table, so the time does not depend on the row count.
How do you delete millions of rows without locking the table for long?
Delete in batches, e.g. DELETE FROM logs WHERE created_at < '2025-01-01' LIMIT 10000; in a loop, so each transaction is short. For a full purge of old data, partitioned tables let you DROP PARTITION instantly.

What is the logical order of execution of a SELECT query?

MySQL Basics 6 min read Difficulty: Beginner 5 of 55
Definition

SQL is written in the order SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY → LIMIT, but it is logically evaluated as FROM/JOIN → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → LIMIT.

Why interviewers ask: This one fact explains many errors: why a SELECT alias cannot be used in WHERE, why aggregates are not allowed in WHERE, and why ORDER BY can use aliases.
Logical Query Processing WHERE HAVING Alias ORDER BY
How It Works — Step by Step
Step 1 / 7
  1. 1FROM (and any JOINs) runs first and builds the working set: all 10 employees.
  2. 2WHERE filters individual rows: 8 employees earn more than 60,000. Aggregates and SELECT aliases do not exist yet, so they cannot be used here.
  3. 3GROUP BY collapses the rows into one group per dept_id: departments 10, 20 and 30.
  4. 4HAVING filters groups: department 30 has only one qualifying employee and is removed.
  5. 5SELECT now computes the output columns, including AVG(salary), and creates the alias avg_sal.
  6. 6ORDER BY runs after SELECT, which is why it can use the alias avg_sal.
  7. 7LIMIT is last: only the top row is returned. (DISTINCT, when present, runs between SELECT and ORDER BY.)
Example
SQL (MySQL)
-- Works: ORDER BY runs after SELECT, so the alias exists
SELECT dept_id, AVG(salary) AS avg_sal
FROM employees
WHERE salary > 60000
GROUP BY dept_id
HAVING COUNT(*) >= 2
ORDER BY avg_sal DESC
LIMIT 1;

-- Fails: WHERE runs before SELECT, the alias does not exist yet
SELECT name, salary * 12 AS annual FROM employees WHERE annual > 1000000;
Output
+---------+---------------+
| dept_id | avg_sal       |
+---------+---------------+
|      10 | 115000.000000 |
+---------+---------------+
ERROR 1054 (42S22): Unknown column 'annual' in 'where clause'
Note: This is the logical order that defines the result. The optimizer may physically do things differently (for example, read rows already sorted from an index so no ORDER BY sort is needed), but the result must be the same.
Cross Questions
How would you filter on the alias then?
Repeat the expression (WHERE salary * 12 > 1000000) or wrap the query in a derived table / CTE and filter outside.
Can HAVING use a SELECT alias in MySQL?
Yes. MySQL allows aliases in GROUP BY and HAVING as an extension to standard SQL. Many other databases do not, so repeating the expression is more portable.

WHERE filters rows before grouping. HAVING filters groups after GROUP BY, so it can use aggregate functions such as COUNT() and SUM().

FROM employees
WHERE hire_date >= '2019-01-01'      -- row filter

Put every condition that does not need an aggregate in WHERE. Filtering early means fewer rows to group, and WHERE can use an index. HAVING dept_id = 10 works but is wasteful.

Cross Questions
Can you use HAVING without GROUP BY?
Yes: the whole table is one group. SELECT COUNT(*) FROM employees HAVING COUNT(*) > 5; returns one row or nothing.

Cross Questions
What does '%' mean in 'user'@'%'?
Any host. 'user'@'10.0.%' limits logins to that subnet, and 'user'@'localhost' to the same machine.
Do you need FLUSH PRIVILEGES after GRANT?
No. GRANT, REVOKE and CREATE USER reload privileges automatically. FLUSH PRIVILEGES is only needed if the grant tables were edited directly with INSERT/UPDATE.

How does GROUP BY work? Explain COUNT(*), COUNT(col) and COUNT(DISTINCT col)

Filtering, Aggregation & Functions 7 min read Difficulty: Basic 10 of 55
Definition

GROUP BY collapses rows that share the same value(s) into one group, and aggregate functions (COUNT, SUM, AVG, MIN, MAX) compute one value per group.

GROUP BY COUNT SUM AVG MIN MAX DISTINCT
How It Works — Step by Step
Step 1 / 5
  1. 1The query is SELECT dept_id, COUNT(*), SUM(salary) FROM employees GROUP BY dept_id HAVING COUNT(*) >= 2. It starts from the 10 rows of employees.
  2. 2GROUP BY dept_id puts rows with the same department into one bucket. Note that all NULL departments go into one NULL group.
  3. 3Aggregate functions run once per bucket: each group gets its own COUNT and SUM.
  4. 4HAVING then filters whole groups. The NULL group has only 1 row, so it is dropped.

Definition

Definition

A shorter version uses plain UNION of the LEFT and RIGHT joins, which removes duplicates. It works here, but it also removes genuine duplicate rows (two employees with the same name in the same department), and the DISTINCT step costs a sort. The UNION ALL + IS NULL version is exact and faster.

Reconciliation between a source system and the warehouse: full outer join on the business key and flag rows as missing in target (right side NULL), missing in source (left side NULL) or mismatch (both present, values differ).

What is the difference between putting a condition in ON vs WHERE in a LEFT JOIN?

Joins 6 min read Difficulty: Intermediate 19 of 55
Definition

For an INNER JOIN, a filter in ON or WHERE gives the same result. For a LEFT JOIN it does not:

A condition in ON only controls which right-side rows match; every left row is still kept. A condition on the right table in WHERE runs after the join and removes the NULL-extended rows, turning the LEFT JOIN into an INNER JOIN.

LEFT JOIN ON Clause WHERE Clause Outer Join Filter
How It Works — Step by Step
Step 1 / 4
  1. 1Goal: list every department with its employees earning above 1,00,000, keeping departments that have none. The first query puts the salary condition in the ON clause.
  2. 2With the condition in ON, it only decides which employees match. HR and Marketing find no matching employee, so LEFT JOIN keeps them with NULLs. Result: 6 rows, all 4 departments.
  3. 3The second query puts the condition in WHERE. First the LEFT JOIN produces all 10 department–employee rows (Marketing with NULLs).
  4. 4Then WHERE filters the joined rows. Low earners are removed, and so is the Marketing row, because NULL > 100000 is unknown. The LEFT JOIN has silently become an INNER JOIN. Rule: conditions on the right-hand table of a LEFT JOIN go in ON.
Example

FROM departments d
LEFT JOIN employees e ON d.dept_id = e.dept_id AND e.salary > 100000
ORDER BY d.dept_id, e.salary DESC;

-- Condition in WHERE: HR and Marketing disappear
SELECT d.dept_name, e.name, e.salary
FROM departments d
LEFT JOIN employees e ON d.dept_id = e.dept_id
WHERE e.salary > 100000
ORDER BY d.dept_id, e.salary DESC;

Why does a join return more rows than expected? (Row multiplication / fan-out)

Definition

A join returns one row for every matching pair. If the join key is not unique on one side, rows from the other side are repeated. Aggregating a column after such a join inflates the totals.

Habit: Before writing any join, ask: "What is the grain (one row per what) of each table, and of the result?"
Fan-out Grain Duplicates Many-to-Many Pre-aggregation
How It Works — Step by Step
Step 1 / 5
  1. 1Three orders whose amounts add up to 78,000. One row per order.
  2. 2The order_items table has one row per product, so orders 101 and 105 appear twice. The join key is not unique on this side.
  3. 3A join returns one row per matching pair. Each order row is repeated once for each of its items: 3 orders become 5 rows, and amount is copied onto every copy.
  4. 4Summing the order amount after the join counts orders 101 and 105 twice: 1,48,000 instead of 78,000. This "fan-out" bug is very common in reporting queries.
  5. 5Sum order amounts from orders alone, or pre-aggregate order_items in a subquery/CTE (one row per order) before joining. SUM(DISTINCT amount) is not a fix: two different orders can have the same amount.
Example

-- Right: revenue from orders alone
SELECT SUM(amount) AS revenue FROM orders WHERE status <> 'CANCELLED';

-- Right, when item data is also needed: aggregate items first

FROM orders o
JOIN (SELECT order_id, COUNT(*) AS items FROM order_items GROUP BY order_id) i
  ON i.order_id = o.order_id
WHERE o.order_id IN (101, 102, 105);

Min 0 (no matches). Max 20, if every row matches every row (e.g. all join keys are the same value). LEFT JOIN: min 5, max 20.

What is a recursive CTE? Write one for an employee hierarchy and a date series

Definition

A recursive CTE refers to itself. It has an anchor member (the starting rows) and a recursive member joined to the previous iteration's rows, combined with UNION ALL. It repeats until an iteration returns no rows.

WITH RECURSIVE Anchor Member Recursive Member Hierarchy Date Series cte_max_recursion_depth
How It Works — Step by Step
Step 1 / 5
  1. 1The anchor member runs once: SELECT … FROM employees WHERE manager_id IS NULL returns the top of the tree, Arjun, at level 1.
  2. 2The recursive member joins employees to the rows produced in the previous step (e.manager_id = cte.emp_id): Arjun's 4 direct reports, level 2.
  3. 3It runs again using only the new rows from iteration 1, finding their reports: 5 employees at level 3. Divya has no reports.
  4. 4Iteration 3 joins against the level-3 rows and finds nothing. An empty result ends the recursion.
  5. 5All iterations are combined with UNION ALL. MySQL stops with an error if recursion goes deeper than cte_max_recursion_depth (default 1000), which protects against cycles.

    SELECT emp_id, name, manager_id, 1 AS level, CAST(name AS CHAR(200)) AS path
    FROM employees WHERE manager_id IS NULL                 -- anchor
    UNION ALL
    SELECT e.emp_id, e.name, e.manager_id, o.level + 1, CONCAT(o.path, ' > ', e.name)
    FROM employees e JOIN org o ON e.manager_id = o.emp_id  -- recursive member
)
SELECT level, name, path FROM org ORDER BY path;

What is the difference between ROW_NUMBER, RANK and DENSE_RANK?

Definition

All three number the rows of each partition in the given order. They differ only in how they treat ties: ROW_NUMBER always gives unique numbers, RANK gives ties the same number and leaves gaps, DENSE_RANK gives ties the same number without gaps.

ROW_NUMBER RANK DENSE_RANK Ties Top-N
How It Works — Step by Step
Step 1 / 5
  1. 1All three functions number rows in the order given by OVER (ORDER BY salary DESC). Rahul and Sneha both earn 95,000: a tie.
  2. 2ROW_NUMBER() gives every row a unique number 1, 2, 3 … Ties are broken arbitrarily (add a second ORDER BY column to make it deterministic).
  3. 3RANK() gives tied rows the same rank (5, 5) and then skips: the next rank is 7, like positions in a race.
  4. 4DENSE_RANK() also gives ties the same rank but does not skip: the next rank is 6.
  5. 5So for "the 6th highest distinct salary" use DENSE_RANK = 6 (82,000). RANK has no row with 6 at all.

Definition

Running Total Moving Average Frame ROWS RANGE UNBOUNDED PRECEDING
How It Works — Step by Step
Step 1 / 4
  1. 1A running total is SUM(sales) OVER (ORDER BY day): each row adds its sales to everything before it.
  2. 2The frame for day 4 is every row from the start up to the current row (days 1–4): 100 + 300 + 200 + 400 = 1000. The frame grows by one row each day.
  3. 3A 3-day moving average uses a frame of fixed size: the current row and the two before it.

How do you find and delete duplicate rows?

Definition

Duplicates are rows that repeat the same business key (e.g. the same email) even though the surrogate id differs. Find them with GROUP BY … HAVING COUNT(*) > 1, then delete all but one copy per key using ROW_NUMBER() or a self-join.

Duplicates GROUP BY HAVING ROW_NUMBER DELETE JOIN Deduplication
Example
SQL (MySQL)
CREATE TABLE subscribers (id INT AUTO_INCREMENT PRIMARY KEY, email VARCHAR(40), city VARCHAR(20));
INSERT INTO subscribers (email, city) VALUES
 ('asha@x.com', 'Mumbai'), ('ravi@x.com', 'Pune'), ('asha@x.com', 'Mumbai'),
 ('neha@x.com', 'Delhi'),  ('ravi@x.com', 'Pune'), ('asha@x.com', 'Thane');

-- 1. Which keys are duplicated, and how often?

FROM subscribers GROUP BY email HAVING COUNT(*) > 1;

-- 2. Show every duplicate row except the first (lowest id) per email

    SELECT id, email, ROW_NUMBER() OVER (PARTITION BY email ORDER BY id) AS rn
    FROM subscribers

Find users who logged in on 3 or more consecutive days (Gaps and Islands)

SQL Coding Round 9 min read Difficulty: Advanced 38 of 55
Definition

Gaps and islands problems ask for runs of consecutive values (islands) separated by missing values (gaps). The standard trick: within an island, value − ROW_NUMBER() is constant, so it can be used as a group key.

Gaps and Islands Consecutive Streak ROW_NUMBER Date Arithmetic
How It Works — Step by Step
Step 1 / 5
  1. 1One user's login dates, sorted. Some days are consecutive and some have gaps. We want each unbroken streak (an island).
  2. 2Number the rows in date order with ROW_NUMBER(). Inside a streak, the date and the row number both go up by exactly 1.
  3. 3So date − row_number stays constant inside a streak and changes after every gap. That constant is a group key for the island.
  4. 4Group by that key: MIN(date) is the start, MAX(date) the end, COUNT(*) the length. Three islands of 3, 2 and 4 days.
  5. 5Filter with HAVING to answer "users who logged in on 3 or more consecutive days". The same trick finds consecutive seat numbers, salary-increase streaks and so on.
Example: All Streaks of 3+ Days
SQL (MySQL)
WITH numbered AS (
    SELECT user_id, login_date,
           login_date - INTERVAL ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY login_date) DAY AS grp
    FROM logins
),
streaks AS (
    SELECT user_id, MIN(login_date) AS streak_start, MAX(login_date) AS streak_end, COUNT(*) AS days
    FROM numbered
    GROUP BY user_id, grp
)
SELECT * FROM streaks
WHERE days >= 3
ORDER BY user_id, streak_start;

How do you calculate the median in MySQL?

SQL Coding Round 6 min read Difficulty: Advanced 41 of 55
Definition

The median is the middle value of the sorted data, or the average of the two middle values when the count is even. MySQL has no MEDIAN() or PERCENTILE_CONT function, so it is computed with window functions.

Median ROW_NUMBER COUNT OVER Percentile
Example
SQL (MySQL)
-- Overall median salary (10 rows → average of the 5th and 6th)
WITH s AS (
    SELECT salary,
           ROW_NUMBER() OVER (ORDER BY salary) AS rn,
           COUNT(*)     OVER ()                AS cnt
    FROM employees
)
SELECT AVG(salary) AS median_salary
FROM s
WHERE rn IN (FLOOR((cnt + 1) / 2), CEIL((cnt + 1) / 2));

-- Median per department
WITH s AS (
    SELECT dept_id, salary,
           ROW_NUMBER() OVER (PARTITION BY dept_id ORDER BY salary) AS rn,
           COUNT(*)     OVER (PARTITION BY dept_id)                AS cnt
    FROM employees WHERE dept_id IS NOT NULL
)
SELECT dept_id, AVG(salary) AS median_salary
FROM s
WHERE rn IN (FLOOR((cnt + 1) / 2), CEIL((cnt + 1) / 2))
GROUP BY dept_id;

| median_salary |
+---------------+
|  95000.000000 |

+---------+---------------+
| dept_id | median_salary |
+---------+---------------+
|      10 | 107500.000000 |

Why FLOOR and CEIL

For odd cnt, FLOOR and CEIL of (cnt + 1) / 2 are the same row, so the AVG is just that value. For even cnt they are the two middle rows. The same pattern gives other percentiles by changing the position formula.

Find missing IDs or gaps in a sequence

SQL Coding Round 6 min read Difficulty: Advanced 43 of 55
Definition

Gaps appear when rows were deleted, inserts failed, or an extract missed data. Two approaches: compare each value with the next one using LEAD, or generate the full expected sequence (recursive CTE) and anti-join.

Gaps LEAD Recursive CTE Anti-join Data Quality
Example
SQL (MySQL)
CREATE TABLE invoices (invoice_no INT PRIMARY KEY);
INSERT INTO invoices VALUES (1001), (1002), (1003), (1006), (1007), (1010);

-- 1. Gap ranges with LEAD
SELECT invoice_no + 1 AS gap_from, next_no - 1 AS gap_to
FROM (SELECT invoice_no, LEAD(invoice_no) OVER (ORDER BY invoice_no) AS next_no FROM invoices) t
WHERE next_no - invoice_no > 1;

-- 2. Every missing number: generate the full range, then anti-join
SET SESSION cte_max_recursion_depth = 100000;
WITH RECURSIVE seq AS (
    SELECT MIN(invoice_no) AS n, MAX(invoice_no) AS mx FROM invoices
    UNION ALL
    SELECT n + 1, mx FROM seq WHERE n < mx
)
SELECT GROUP_CONCAT(n ORDER BY n) AS missing
FROM seq
WHERE NOT EXISTS (SELECT 1 FROM invoices i WHERE i.invoice_no = seq.n);

| gap_from | gap_to |

|     1004 |   1005 |
|     1008 |   1009 |

+---------------------+
| 1004,1005,1008,1009 |

  • Index for the query: equality columns first, then the range or ORDER BY column. A composite index can filter and deliver rows already sorted.
  • Make predicates sargable: no functions or casts on indexed columns.
  • Read less: select only needed columns (enables covering indexes), filter early, avoid fan-out joins, use keyset pagination.
  • Rewrite: correlated subqueries → joins or window functions; OR → UNION ALL; huge IN lists → join to a temp table.
  • Check the environment: statistics (ANALYZE TABLE), buffer pool size vs data size, lock waits.

Why is LIMIT with a large OFFSET slow? What is keyset pagination?

Performance & Query Tuning 7 min read Difficulty: Expert 47 of 55
Definition

LIMIT 10 OFFSET 100000 must read and discard the first 1,00,000 rows before returning 10, so each deeper page is slower. Keyset (seek) pagination remembers the last key of the previous page and asks for WHERE key > last_key ORDER BY key LIMIT 10, which is an index seek costing the same for every page.

Pagination LIMIT OFFSET Keyset Pagination Seek Method
How It Works — Step by Step
Step 1 / 4
  1. 1The first page is cheap: MySQL reads 10 rows from the start of the index and stops.
  2. 2For page 10,001 with OFFSET 100000, MySQL cannot jump to row 1,00,001. It must walk through 1,00,000 rows and discard them before returning 10. Cost grows with page depth.
  3. 3Keyset (seek) pagination filters on the last key seen. order_id > 100000 is an index range, so MySQL jumps straight there and reads only 10 rows, at any depth.
  4. 4Trade-offs: you can only go next/previous, not jump to "page 537", and the sort key must be unique (add the id as a tie-breaker, e.g. (created_at, id) > (?, ?)).

How do you do an upsert in MySQL? Compare ON DUPLICATE KEY UPDATE, REPLACE and INSERT IGNORE

MySQL for Data Engineering 8 min read Difficulty: Expert 50 of 55
Definition

An upsert inserts a row if its key is new and updates it if the key already exists. MySQL has no MERGE statement; it offers INSERT … ON DUPLICATE KEY UPDATE, REPLACE and INSERT IGNORE. All of them detect "exists" through a PRIMARY KEY or UNIQUE index.

Upsert ON DUPLICATE KEY UPDATE REPLACE INSERT IGNORE Idempotent Load
How It Works — Step by Step
Step 1 / 5
  1. 1A pipeline delivers a batch with a changed row (Ravi) and a new row (Neha). We want one statement that inserts new keys and updates existing ones: an upsert.
  2. 2MySQL tries to insert id 2, hits the PRIMARY KEY (or any UNIQUE key) and, instead of failing, runs the ON DUPLICATE KEY UPDATE part on the existing row.
  3. 3id 3 causes no conflict, so it is inserted normally.
  4. 4Result: one statement, idempotent (running the same batch again gives the same table). Row-count tip: MySQL reports 1 per insert and 2 per update (0 if the update changed nothing).
  5. 5REPLACE looks similar but is delete + insert. Columns you did not supply lose their values, ON DELETE CASCADE can wipe child rows, and the auto-increment id changes. Prefer ON DUPLICATE KEY UPDATE for upserts.
Example
SQL (MySQL)
CREATE TABLE accounts (id INT PRIMARY KEY, name VARCHAR(20), balance INT,
                       updated_at DATETIME DEFAULT '2026-01-01 00:00:00');
INSERT INTO accounts (id, name, balance) VALUES (1, 'Asha', 500), (2, 'Ravi', 300);

-- Upsert (MySQL 8.0.19+ row alias syntax)
INSERT INTO accounts (id, name, balance) VALUES (2, 'Ravi', 450), (3, 'Neha', 200) AS new
ON DUPLICATE KEY UPDATE balance = new.balance, updated_at = '2026-10-11 09:00:00';
SELECT ROW_COUNT() AS affected;          -- 2 for the update + 1 for the insert
SELECT * FROM accounts;

-- INSERT IGNORE: skips the conflicting row (with a warning), inserts the rest
INSERT IGNORE INTO accounts (id, name, balance) VALUES (1, 'Asha', 999), (4, 'Imran', 50);
SELECT id, balance FROM accounts WHERE id IN (1, 4);

-- REPLACE: deletes row 2 and inserts a new one; updated_at falls back to the default
REPLACE INTO accounts (id, name, balance) VALUES (2, 'Ravi', 475);
SELECT * FROM accounts WHERE id = 2;

What is the MySQL binary log? How is it used for replication and Change Data Capture (CDC)?

MySQL for Data Engineering 9 min read Difficulty: Expert 53 of 55
Definition

The binary log (binlog) is MySQL's ordered record of every committed change. Replicas replay it to stay in sync, it enables point-in-time recovery, and CDC tools such as Debezium read it to stream inserts, updates and deletes to Kafka and on into a data lake or warehouse.

Binary Log binlog_format ROW GTID Replication Debezium CDC
Comparison
binlog_formatWhat is loggedNotes
STATEMENTThe SQL statement textSmall, but non-deterministic statements (NOW(), UUID(), LIMIT without ORDER BY) can differ on replicas
ROW (default since 5.7.7)Before/after image of every changed rowExact and required for CDC; larger for bulk updates

How It Works — Step by Step
Step 1 / 6
  1. 1The application changes rows normally. Nothing in the application needs to know about CDC.
  2. 2On commit, MySQL writes every change to the binary log. In ROW format each event carries the before and after values of the row, including DELETEs.
  3. 3A CDC connector such as Debezium connects as if it were a replica and reads the binlog stream, turning each event into a change record (op = c/u/d, before, after).
  4. 4Changes are published to Kafka, usually one topic per table, in commit order per key.
  5. 5A sink job (Spark, Flink, Kafka Connect) applies them to the lake or warehouse, typically a MERGE keeping the latest change per primary key.
  6. 6The connector stores its position (binlog file + offset or GTID) so it resumes exactly where it stopped. It first takes a consistent snapshot of existing rows, then switches to streaming.

How do you extract data from MySQL into a data lake incrementally? (Spark JDBC partitioned reads)

MySQL for Data Engineering 9 min read Difficulty: Expert 54 of 55
Definition

A typical batch extract reads only rows changed since the last run (a watermark on updated_at or an increasing id), splits the read into parallel chunks by a numeric key, and writes Parquet/Delta files to the lake. Spark's JDBC source does the chunking with partitionColumn, lowerBound, upperBound and numPartitions.

Spark JDBC partitionColumn numPartitions fetchsize Watermark Read Replica
Example: Planning the Extract in SQL
SQL (MySQL)
-- 1. Find the bounds of this run's delta (watermark from the previous successful run)
SET @last_watermark = '2026-02-01';
SELECT MIN(order_id) AS lower_bound, MAX(order_id) AS upper_bound, COUNT(*) AS rows_to_extract,
       MAX(order_date) AS new_watermark
FROM orders
WHERE order_date > @last_watermark;

-- 2. What each of 2 Spark tasks will run (Spark generates these ranges)
SELECT 'task 1' AS task, COUNT(*) AS rows_read FROM orders WHERE order_date > @last_watermark AND order_id < 108
UNION ALL
SELECT 'task 2', COUNT(*) FROM orders WHERE order_date > @last_watermark AND order_id >= 108;

The Spark Job
PySpark
bounds = spark.read.jdbc(url, f"(SELECT MIN(order_id) lo, MAX(order_id) hi FROM orders "
                              f" WHERE updated_at > '{last_watermark}') b", properties=props).first()

df = (spark.read.format("jdbc")
      .option("url", "jdbc:mysql://replica-host:3306/shop")       # read from a replica
      .option("dbtable", f"(SELECT * FROM orders WHERE updated_at > '{last_watermark}') src")
      .option("partitionColumn", "order_id")                      # numeric/date column
      .option("lowerBound", bounds.lo).option("upperBound", bounds.hi)
      .option("numPartitions", 8)                                  # 8 parallel queries
      .option("fetchsize", 10000)                                  # rows per round trip
      .option("user", user).option("password", password)
      .load())

Common Misunderstanding: lowerBound and upperBound only decide how the range is split; they do not filter. Rows outside the bounds still go into the first and last partitions. A skewed key (most ids in one range) gives one slow task, so pick an evenly distributed column.
Good Practice
  • Read from a replica, not the primary, so extracts never slow the application.
  • Index the watermark column (updated_at), otherwise every run is a full scan.
  • Use > the previous watermark and allow a small overlap for late commits, then deduplicate downstream (MERGE on the key).
  • Store the watermark only after the data is safely written, so a failed run is simply repeated.
  • Query-based extraction cannot see hard DELETEs; use soft deletes or log-based CDC when deletes matter.
Cross Questions
Why not one big JDBC read?
A single connection reads serially through one cursor on one executor: slow, and it may run out of memory. Partitioned reads run numPartitions queries in parallel.
What happens if numPartitions is too high?
Each partition is a separate connection and query on MySQL. Too many can overload the source; 4–16 is typical.

How do you back up and restore a MySQL database? Explain logical vs physical backups and point-in-time recovery

MySQL for Data Engineering 7 min read Difficulty: Expert 55 of 55
Definition

A logical backup exports SQL statements or data files (mysqldump, MySQL Shell dump utilities). A physical backup copies the InnoDB data files themselves (Percona XtraBackup, MySQL Enterprise Backup). Point-in-time recovery (PITR) restores the last full backup and then replays the binary logs up to a chosen moment.

mysqldump --single-transaction XtraBackup Point-in-time Recovery MySQL Shell

AspectLogical (mysqldump / Shell)Physical (XtraBackup)

Commands
Shell
# Consistent logical backup of InnoDB tables without locking them
mysqldump --single-transaction --routines --triggers --events \
          --source-data=2 shop | gzip > shop_2026-10-11.sql.gz

# Restore
gunzip < shop_2026-10-11.sql.gz | mysql shop

# Faster, parallel dump and load with MySQL Shell
mysqlsh root@db -- util dump-schemas shop --outputUrl=/backups/shop_2026-10-11
mysqlsh root@db -- util load-dump /backups/shop_2026-10-11

# Point-in-time recovery: replay binlogs after the backup, stop before the bad statement
mysqlbinlog --start-position=157 --stop-datetime="2026-10-11 14:29:59" \
            binlog.000012 binlog.000013 | mysql

--single-transaction starts a REPEATABLE READ transaction, so the dump is a consistent snapshot of all InnoDB tables while the application keeps writing. --source-data=2 records the binlog position of that snapshot as a comment, which is the starting point for PITR or for setting up a replica.

Interview Tip

A backup is only proven by a restore test. Mention scheduled restores into a test server, off-site copies, and monitoring of backup size and duration.

Cross Questions
Someone ran DELETE without WHERE at 14:30. How do you recover?
Restore the latest full backup to a new server, replay the binlog from the backup position up to just before 14:30 (--stop-datetime or the exact position found with mysqlbinlog), verify, then copy the table back.
Is a replica a backup?
No. A replica copies mistakes too: the DELETE reaches it within seconds. A delayed replica (SOURCE_DELAY) can help, but proper backups are still needed.
