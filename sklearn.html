What is machine learning? What are supervised, unsupervised and reinforcement learning? What is scikit-learn?

Machine Learning Foundations 8 min read Difficulty: Beginner 1 of 40
Definition

Machine learning builds models that learn patterns from data instead of following hand-written rules. Supervised learning learns a mapping from features X to a known target y: regression for numbers, classification for categories. Unsupervised learning finds structure without labels: clustering, dimensionality reduction, anomaly detection. Reinforcement learning trains an agent through rewards.

scikit-learn is the standard open-source Python library for classical ML on tabular data: preprocessing, regression, classification, clustering, model selection and pipelines, all with one consistent API, built on NumPy and SciPy.

machine learning supervised unsupervised regression classification scikit-learn
Analogy
Teaching a child to recognise fruit: supervised is showing pictures with names ("this is a mango"); unsupervised is giving a basket and letting them sort similar fruit into piles; reinforcement is a game where they get a sweet for every right pick.
How It Works — Step by Step
Step 1 / 5
  1. 1Supervised learning uses examples with known answers (labels): predict a number (regression) or a category (classification).
  2. 2Unsupervised learning has no labels: it finds groups (clustering) or simpler representations (dimensionality reduction).
  3. 3Reinforcement learning trains an agent by trial, error and reward; scikit-learn does not cover it.
  4. 4The key shift: instead of writing rules, you give data plus answers and the algorithm learns the rules.
  5. 5scikit-learn is the standard Python library for classical machine learning on tables of data.
Real-World Scenario
ML at C-DAC

Regression: predict a student's final exam score from attendance, study hours and mock tests. Classification: flag students at risk of not being placed early enough to help. Clustering: group students by learning pattern to plan remedial batches.

Industry

Credit scoring, churn prediction, demand forecasting, fraud detection and recommendation shortlists are mostly classical supervised models on tables of data, which is exactly scikit-learn's territory; images, audio and text generation use deep learning (TensorFlow/PyTorch).

No; it has only a basic MLPClassifier. Deep learning uses PyTorch or TensorFlow/Keras, often with scikit-learn for preprocessing and evaluation.

Explain the scikit-learn estimator API: fit, predict, transform, fit_transform and score.

Machine Learning Foundations 7 min read Difficulty: Beginner 2 of 40
Definition

Every scikit-learn object is an estimator created with hyperparameters in its constructor and trained with fit(X, y). Predictors (models) add predict (and often predict_proba, decision_function, score). Transformers (scalers, encoders, imputers, PCA) add transform and fit_transform.

X is a 2-D array/DataFrame of shape (n_samples, n_features); y is 1-D (n_samples,). Attributes learned during fit end with an underscore (coef_, mean_, classes_); hyperparameters are read with get_params() and changed with set_params().

fit predict transform fit_transform estimator hyperparameters
Analogy
Every appliance in a kitchen has the same buttons: fit (learn the recipe), predict (cook a dish), transform (chop or blend ingredients). Once you know the buttons, you can use any appliance.
How It Works — Step by Step
Step 1 / 5
  1. 1Data is a 2-D feature matrix X (rows = samples, columns = features) and a target vector y.
  2. 2fit learns the parameters from training data; learned attributes get a trailing underscore.
  3. 3predict applies the learned model to new rows.
  4. 4Transformers (scalers, encoders, imputers) use fit + transform to change the data instead of predicting.
  5. 5score gives a default metric. Because every estimator shares this API, algorithms are interchangeable.
Real-World Scenario
Swapping algorithms painlessly

A team compared logistic regression, random forest and gradient boosting for placement prediction by changing one line each; preprocessing, evaluation and reporting code stayed identical because every model has fit/predict/score.

Cross Questions
fit_transform vs fit then transform?
Same result on the same data; fit_transform can be more efficient. On test data call only transform, never fit_transform.
Why is the training accuracy of the random forest so high?
It is evaluated on the data it learned from; forests can nearly memorise training data. Only test/CV scores tell you about generalisation.
Why must X be 2-D even for one feature?
The API always expects (n_samples, n_features); use X.reshape(-1, 1) or df[["col"]].

Why do we split data into training and test sets? What do random_state and stratify do?

Machine Learning Foundations 7 min read Difficulty: Beginner 3 of 40
Definition

A model must be judged on data it has not seen during training; otherwise we measure memorisation, not generalisation. train_test_split(X, y, test_size=0.2) randomly holds back a test set, used once at the end. During development, compare and tune models on a validation set or with cross-validation on the training data.

random_state fixes the shuffle so the split is reproducible. stratify=y keeps the class proportions identical in train and test, essential for imbalanced classes. Time-ordered data must be split by time; grouped data (several rows per student) by group.

train_test_split test set validation set stratify random_state
Analogy
A teacher who sets the exam using the exact questions from the practice sheet learns nothing about understanding. The test set is the unseen exam paper, locked in a cupboard until the end.
How It Works — Step by Step
Step 1 / 5
  1. 1The full labelled dataset.
  2. 2A random 20 % is held back as the test set; the model only ever learns from the other 80 %.
  3. 3train_test_split does this in one call.
  4. 4Fix random_state for reproducible results and use stratify=y so rare classes appear in both parts.
  5. 5For time-ordered data the test set must come after the training period.
Real-World Scenario
Placement model review

A model reported 96 % accuracy, measured on the training data. On a proper held-out set it scored 78 %. Since then every report shows the stratified test-set score and the split's random_state, so anyone can reproduce it.

Steps to Split Correctly
  1. Split first
    Before any fitting, scaling or feature selection.
  2. Choose the size
    20–30 % test for small data; less for very large data.
  3. Stratify classification targets
    stratify=y.
  4. Fix the seed

Cross Questions
Why not use the test set for tuning?
Every decision based on it leaks information; after enough tuning the test score becomes optimistic. Tune with validation/CV, test once.
What if the dataset is small?
Use cross-validation for model selection and a test set (or nested CV) for the final estimate; a single small split is noisy.
Does stratify work for regression?
Not directly; bin the target (e.g. pd.qcut) and stratify on the bins if needed.

What are overfitting and underfitting? Explain the bias-variance trade-off.

Machine Learning Foundations 8 min read Difficulty: Beginner 4 of 40
Definition

Underfitting: the model is too simple to capture the real pattern: high error on both training and test data (high bias). Overfitting: the model fits noise in the training data: very low training error, much higher test error (high variance, i.e. it changes a lot with different training samples).

Remedies for overfitting: simpler model, regularisation (C, alpha, max_depth, min_samples_leaf), more data, feature selection, ensembling, early stopping. For underfitting: more expressive model, better features, less regularisation. Diagnose with train vs validation scores and learning curves.

overfitting underfitting bias variance regularisation generalisation
Analogy
An underfitting student learns only "the answer is usually C" and fails every exam. An overfitting student memorises last year's paper word for word and fails when the questions change. A good student learns the concepts.
How It Works — Step by Step
Step 1 / 5
  1. 1Data points with a roughly linear trend plus noise.
  2. 2Underfitting: the model is too simple to capture the trend; it is wrong on training and test data alike.
  3. 3A good fit captures the trend and ignores the noise, so it generalises to new data.
  4. 4Overfitting: the model follows the noise of the training points; training error is tiny but new data is predicted badly.
  5. 5This is the bias-variance trade-off; model complexity, regularisation and data size move you along it.
Real-World Scenario
Decision tree depth

An unlimited-depth tree reached 100 % training accuracy on placement data and much lower test accuracy; limiting depth to 3–5 traded a little training accuracy for better test accuracy. The example shows the same pattern with real numbers.

Steps to Diagnose Fit
  1. Compare train and validation scores
    Both low → underfit; big gap → overfit.
  2. Adjust complexity
    Depth, number of features, polynomial degree, regularisation strength.
  3. Add data or augment

Cross Questions
Can a model have high bias and high variance?
Yes, e.g. a poorly chosen model on tiny noisy data; but typically increasing complexity lowers bias and raises variance.
How does regularisation reduce overfitting?
It penalises large or many parameters, forcing simpler functions that generalise better.
Why is 100 % training accuracy a warning sign?
Real data contains noise; fitting it perfectly usually means memorising it.

Walk through a complete machine-learning workflow, from problem definition to a deployed model.

Machine Learning Foundations 9 min read Difficulty: Beginner 5 of 40
Definition

A typical supervised workflow: (1) define the target, the decision it supports and the success metric; (2) collect and explore data; (3) split off a test set; (4) prepare features (cleaning, imputation, encoding, scaling, feature engineering) inside a pipeline; (5) train baseline and candidate models and tune them with cross-validation; (6) evaluate once on the test set; (7) interpret errors and feature effects; (8) deploy the saved pipeline and monitor performance and data drift.

Always compare with a baseline (e.g. DummyClassifier predicting the majority class) to know whether the model adds value.

ML workflow baseline DummyClassifier pipeline evaluation
Analogy
Building a model is like cooking for an event: decide the menu and who is coming (problem, metric), buy and clean ingredients (data), cook and taste in the kitchen (train, validate), serve to guests once (test), then watch whether people enjoy it (monitoring).
How It Works — Step by Step
Step 1 / 8
  1. 1Define what to predict and how success is measured (e.g. recall of at-risk students).
  2. 2Collect and explore the data: types, missing values, distributions, target balance.
  3. 3Hold out a test set before doing anything that learns from data.
  4. 4Prepare features (imputation, encoding, scaling), fitting these steps on training data only.
  5. 5Train candidate models and tune them with cross-validation on the training data.
  6. 6Evaluate the chosen model once on the untouched test set.
  7. 7Look at errors and important features: does the model make sense?
  8. 8Save the whole pipeline, use it for predictions, and monitor it over time.
Real-World Scenario
At-risk student alerts

Goal: by week 6, flag students unlikely to be placed so mentors can intervene. Metric: recall of at-risk students at acceptable precision. Features available at week 6 only (attendance, hours, mock test, course). How do you handle missing values in scikit-learn? SimpleImputer, KNNImputer and missing indicators.

Definition

Definition

A Pipeline chains transformers and a final estimator into one estimator: fit fits each step in order on the training data, predict pushes new data through the same steps. Benefits: no leakage in cross-validation, one object to tune (step__param names in GridSearchCV), one object to save and deploy, raw DataFrames in, predictions out. make_pipeline/make_column_transformer name steps automatically; set_output(transform="pandas") keeps DataFrame outputs.

What is data leakage? Give examples and show how to prevent it.

Data Preprocessing & Pipelines 8 min read Difficulty: Basic 10 of 40
Definition

Data leakage is when information that would not be available at prediction time (or that comes from the evaluation data) is used during training, producing over-optimistic scores that do not hold in production.

Common forms: preprocessing leakage (scaling, imputation or feature selection fitted on all data before splitting/CV); target leakage (features derived from or recorded after the outcome); train-test contamination (duplicates or the same entity in both); temporal leakage (future data predicting the past). Prevention: split first, keep all fitting inside a Pipeline, audit each feature's timing, and use group/time-aware splits.

data leakage target leakage Pipeline cross-validation feature selection
Analogy
Leakage is a student who has seen the answer key: the practice scores are brilliant, and the real exam goes badly.
How It Works — Step by Step
Step 1 / 5
  1. 1Fitting a scaler, imputer or feature selector on all data before splitting leaks test-set statistics into training.
  2. 2Features that are only known after the outcome (final exam score when predicting placement at mid-course) leak the answer.
  3. 3The same entity in both train and test, or future information in training, inflates scores.
  4. 4The tell-tale sign is a model that looks too good to be true and fails on real new data.
  5. 5Prevention: split before any fitting, keep preprocessing inside a Pipeline, check every feature's availability at prediction time, and use group- or time-aware splits.
Real-World Scenario

With many random features, selecting the "best" ones using all rows and then cross-validating gives impressive scores even when the target is pure noise. Doing the selection inside the pipeline reveals the truth: about 50 %, a coin toss. The example reproduces this classic trap.

How does linear regression work? How do you interpret its coefficients?

Regression 8 min read Difficulty: Basic 11 of 40
Definition

Linear regression models the target as a weighted sum of features: ŷ = b₀ + b₁x₁ + … + bₙxₙ. Ordinary least squares chooses the coefficients that minimise the sum of squared residuals. In scikit-learn: LinearRegression().fit(X, y), then intercept_ and coef_.

Interpretation: a coefficient is the expected change in y for a one-unit increase in that feature, holding the other features constant. Coefficients are comparable in size only if features are on the same scale (standardise first), and they are unreliable when features are strongly correlated (multicollinearity).

linear regression OLS coefficients intercept multicollinearity
Analogy
A coefficient is a price list: "each extra weekly study hour is worth about 1.6 marks, each extra attendance point about 0.3", and the intercept is the starting price before anything is added.
How It Works — Step by Step
Step 1 / 5
  1. 1Each point is a student: study hours vs final score.
  2. 2Linear regression fits ŷ = intercept + coefficients × features.
  3. 3It chooses the coefficients that minimise the sum of squared residuals (vertical distances).
  4. 4Each coefficient is the expected change in the target per unit change in that feature, holding the others fixed.
  5. 5Simple and interpretable, a good baseline, but limited to linear additive relationships unless you engineer features.

How do you evaluate a regression model? Explain MAE, MSE, RMSE and R².

Regression 7 min read Difficulty: Basic 12 of 40
Definition

MAE (mean absolute error): average size of errors, in target units, robust to outliers. MSE: mean squared error, penalises large errors more; RMSE = √MSE, back in target units. R² (coefficient of determination): 1 − SS_res/SS_tot, the share of variance explained relative to always predicting the mean; 1 is perfect, 0 equals the mean baseline, and it can be negative on test data. MAPE: mean absolute percentage error (unstable near zero).

Always compare with a baseline (DummyRegressor) and choose the metric that matches the cost of errors.

MAE MSE RMSE R² DummyRegressor metrics
Analogy
MAE is "on average the weather forecast is 2 °C off". RMSE is a stricter teacher who punishes the big misses heavily. R² asks "how much better is the forecast than just saying 'same as the yearly average' every day?"
How It Works — Step by Step
Step 1 / 5
  1. 1Each prediction has an error (actual − predicted).
  2. 2MAE averages absolute errors: "on average we are 4 marks off".
  3. 3RMSE squares errors first, so large misses count more; always ≥ MAE.
  4. 4R² compares the model with always predicting the mean: 1 is perfect, 0 is no better than the mean.
  5. 5Report errors in the target's units for stakeholders, and compare against a baseline.
Real-World Scenario
Explaining accuracy to coordinators

What is regularisation? Compare Ridge, Lasso and ElasticNet.

Regression 8 min read Difficulty: Basic 13 of 40
Definition

Regularisation adds a penalty on coefficient size to the loss, trading a little bias for lower variance. Ridge (L2): penalty α·Σβ²; shrinks all coefficients, handles correlated features well. Lasso (L1): penalty α·Σ|β|; can set coefficients exactly to zero, performing feature selection. ElasticNet: a mix controlled by l1_ratio.

Larger α means stronger shrinkage. Choose α with cross-validation (RidgeCV, LassoCV, ElasticNetCV). Standardise features first, because the penalty treats all coefficients equally. (In LogisticRegression the equivalent knob is C = 1/strength.)

Ridge Lasso ElasticNet L1 L2 alpha
Analogy
Regularisation is a budget limit on explanations: Ridge makes every feature take a smaller share; Lasso is a strict manager who removes features that do not earn their keep.
How It Works — Step by Step
Step 1 / 5
  1. 1Ordinary least squares gives every feature a coefficient, including noise features, which hurts generalisation.
  2. 2Ridge (L2) adds a penalty on squared coefficients: all shrink towards zero, none reach exactly zero.
  3. 3Lasso (L1) penalises absolute values: weak features are set exactly to zero, giving automatic feature selection.
  4. 4The strength α is a hyperparameter chosen by cross-validation (RidgeCV, LassoCV).
  5. 5ElasticNet combines both penalties; because penalties compare coefficient sizes, features must be scaled.
Real-World Scenario
Many candidate features

With dozens of engineered features (weekly quiz scores, login counts, assignment delays) and a few hundred students, plain regression overfits. LassoCV kept the handful that matter and set the rest to zero; Ridge was more stable when several features were strongly correlated.

How can a linear model capture non-linear relationships? Explain PolynomialFeatures.

Regression 7 min read Difficulty: Basic 14 of 40
Definition

PolynomialFeatures(degree=d) adds powers and interaction terms (x², x₁·x₂, …) as new features. A linear model on these features fits curves while remaining linear in its coefficients ("linear regression with polynomial basis").

Number of features grows quickly with degree and inputs, which increases overfitting risk: combine with scaling and Ridge, and choose the degree with cross-validation. Alternatives: SplineTransformer, log/sqrt transforms, binning, or non-linear models (trees, boosting).

PolynomialFeatures interactions non-linearity SplineTransformer degree
Analogy
A ruler can only draw straight lines; give it a few bendable joints (x², x³) and it can trace a curve. Too many joints and it wiggles through every point, including the noise.
How It Works — Step by Step
Step 1 / 5
  1. 1The data follows a curve (rise then fall).
  2. 2A straight line cannot follow it: underfitting.
  3. 3Adding x² as an extra feature lets a linear model fit a parabola; the model is still linear in its coefficients.
  4. 4High degrees overfit; choose the degree with cross-validation and use regularisation.
  5. 5PolynomialFeatures also creates interaction terms (products of features).
Real-World Scenario
Diminishing returns of study hours

Marks rise quickly with the first few weekly study hours and then flatten. A quadratic term captures this curve; an interaction attendance × hours captures "hours help more when attendance is good".

How do you check whether a regression model is adequate? Residual analysis and assumptions.

Regression 7 min read Difficulty: Basic 15 of 40
Definition

Classical linear regression assumes: a linear relationship, independent errors, constant variance of errors (homoscedasticity), approximately normal errors (for inference), and no extreme multicollinearity.

Check them with residuals (actual − predicted): plot residuals against predictions (patterns → missing non-linearity; funnel → unequal variance), histogram/Q-Q plot for normality, residuals by group or over time, and correlations/VIF among features. For pure prediction, good cross-validated error matters most, but residuals explain where the model fails.

residuals assumptions homoscedasticity multicollinearity diagnostics
Analogy
Residuals are the model's mistakes laid out on a table. Random crumbs mean the recipe is fine; crumbs that form a pattern mean something systematic is wrong with the recipe.
How It Works — Step by Step
Step 1 / 5
  1. 1If the model is adequate, residuals scatter randomly around zero.
  2. 2A curved pattern means the model is missing a non-linear relationship.
  3. 3A funnel shape means errors grow with the prediction (heteroscedasticity); intervals and coefficients become unreliable.
  4. 4Outliers, multicollinearity and time patterns are other things residual analysis reveals.
  5. 5Typical remedies: transform the target, engineer features, or switch to models that capture non-linearity.

How does logistic regression work for classification? What do predict_proba and coefficients mean?

Classification 8 min read Difficulty: Intermediate 16 of 40
Definition

Logistic regression computes a linear score z = b₀ + Σbᵢxᵢ and converts it to a probability with the sigmoid 1/(1+e⁻ᶻ). It is trained by minimising log loss (cross-entropy). predict_proba returns class probabilities; predict applies a 0.5 threshold (for binary problems). Multi-class problems use the multinomial (softmax) form.

Coefficients change the log-odds; np.exp(coef) gives odds ratios (with standardised features: per one standard deviation). scikit-learn applies L2 regularisation by default; C is the inverse strength (smaller C = stronger).

Analogy
Logistic regression is a points system with a dial: every feature adds or removes points, and the dial (sigmoid) turns the total into "probability of placement" between 0 and 100 %, never below or above.

  2. 2The sigmoid function turns z into a probability between 0 and 1.

  4. 4Coefficients act on the log-odds; exponentiated, they are odds ratios, which makes the model explainable.
  5. 5It is a classification model with L2 regularisation by default, controlled by C.

What is a confusion matrix? Explain accuracy, precision, recall and F1-score.

Classification 8 min read Difficulty: Intermediate 17 of 40
Definition

A confusion matrix counts true negatives (TN), false positives (FP), false negatives (FN) and true positives (TP). Accuracy = (TP+TN)/total. Precision = TP/(TP+FP): how many predicted positives are correct. Recall (sensitivity, TPR) = TP/(TP+FN): how many actual positives are found. F1 = harmonic mean of precision and recall. Specificity = TN/(TN+FP).

Choose by cost: missing a positive (FN) is expensive → recall; false alarms (FP) expensive → precision. classification_report shows per-class precision/recall/F1 with macro and weighted averages.

confusion matrix precision recall F1 accuracy classification_report
Analogy
A metal detector at an exam hall: precision is "when it beeps, is it really a phone?"; recall is "of all phones brought in, how many did it catch?". A detector that beeps for everyone has perfect recall and terrible precision.
How It Works — Step by Step
Step 1 / 5
  1. 1The confusion matrix counts correct and incorrect predictions per class.
  2. 2Accuracy is the share of all correct predictions, misleading when classes are imbalanced.
  3. 3Precision: among predicted positives, how many are real.
  4. 4Recall (sensitivity): among real positives, how many we found.
  5. 5F1 balances the two. Choose the metric from the cost of each error type.

Macro averages classes equally (highlights poor minority-class performance); weighted averages by class frequency.
Which metric for a cancer screening test?
High recall (sensitivity) first, then confirm positives with a second, more precise test.

What are the ROC curve and AUC? How do you choose a classification threshold?

Classification 8 min read Difficulty: Intermediate 18 of 40
Definition

The ROC curve plots true-positive rate (recall) against false-positive rate for all thresholds. AUC (area under it) measures ranking quality: the probability that a random positive gets a higher score than a random negative (0.5 random, 1.0 perfect), independent of the threshold. The precision-recall curve and average precision are more informative when positives are rare.

The default 0.5 threshold is arbitrary; choose it from costs or a target (e.g. recall ≥ 0.9), using validation data, via precision_recall_curve/roc_curve, or TunedThresholdClassifierCV (scikit-learn 1.5+).

Analogy
A security scanner with a sensitivity dial: turn it up and it catches more threats but also beeps at belts and coins. The ROC curve shows every dial position at once; AUC says how good the scanner is overall, regardless of where you set the dial.

Step 1 / 5
  1. 1The ROC curve plots true-positive rate against false-positive rate for every possible threshold; the diagonal is random guessing.
  2. 2A better model bows towards the top-left; the area under the curve (AUC) summarises ranking quality independent of the threshold.
  3. 3Each point is a threshold. The default 0.5 is rarely optimal for business costs.
  4. 4Lowering the threshold catches more positives (recall up) at the price of more false alarms.
  5. 5For rare positive classes, the precision-recall curve shows performance more honestly.

How does a decision tree work? What are Gini impurity and entropy? How do you control overfitting?

Trees, Ensembles & SVM 8 min read Difficulty: Intermediate 21 of 40
Definition

A decision tree recursively splits the data with yes/no questions on single features (e.g. mock_test ≤ 68.5), choosing at each node the split that makes the child nodes as pure as possible. Impurity measures: Gini = 1 − Σpᵢ² (default) and entropy = −Σpᵢ log₂ pᵢ (information gain). Regression trees minimise squared error. Leaves predict the majority class (or mean).

Unrestricted trees memorise the training data. Control complexity with max_depth, min_samples_leaf, min_samples_split, max_leaf_nodes, or cost-complexity pruning (ccp_alpha). Trees need no scaling and capture interactions, but a single tree is unstable.

DecisionTreeClassifier Gini entropy max_depth pruning export_text
Analogy
A tree is the "20 questions" game: each question is chosen to rule out as much as possible, until the answer is clear. Asking too many very specific questions just memorises the examples you practised on.
How It Works — Step by Step
Step 1 / 5
  1. 1The root question splits all training students on the most informative feature and threshold.
  2. 2Each branch asks a further question about its subset.
  3. 3Leaves give the predicted class (and a probability from the class mix in the leaf).
  4. 4Splits are chosen greedily to reduce impurity; limits on depth and leaf size control overfitting.
  5. 5Trees are interpretable and need no scaling, but a single tree has high variance, which ensembles fix.

What is a random forest? How do bagging, max_features and out-of-bag scores work?

Trees, Ensembles & SVM 8 min read Difficulty: Intermediate 22 of 40
Definition

A random forest is an ensemble of decision trees, each trained on a bootstrap sample of the rows (bagging) and considering only a random subset of features at each split (max_features, default √n for classification). Predictions are majority votes (or averaged probabilities); for regression, averages.

Averaging many decorrelated, high-variance trees reduces variance, so forests are accurate and robust with little tuning. Rows not drawn for a tree ("out-of-bag") give a free validation estimate (oob_score=True). Key parameters: n_estimators (more = more stable), max_depth/min_samples_leaf, max_features, class_weight, n_jobs=-1.

RandomForestClassifier bagging bootstrap max_features OOB score
Analogy
Instead of trusting one expert, ask 200 experts who each studied a different random sample of past cases and looked at different clues, then take a vote. Individual experts make odd mistakes; the crowd is reliably good.
How It Works — Step by Step
Step 1 / 5
  1. 1Each tree is trained on a bootstrap sample (rows drawn with replacement) and considers a random subset of features at each split.
  2. 2The trees differ, so their individual errors are partly independent.
  3. 3Predictions are combined by majority vote (classification) or averaging (regression).
  4. 4Averaging many high-variance trees reduces variance; rows left out of a bootstrap provide an out-of-bag score.
  5. 5More trees only make results more stable; the forest also reports feature importances and trains in parallel.

How does gradient boosting work? When would you use HistGradientBoosting, XGBoost or LightGBM?

Trees, Ensembles & SVM 9 min read Difficulty: Intermediate 23 of 40
Definition

Gradient boosting builds an additive model of shallow trees sequentially: each new tree is fitted to the negative gradient of the loss (for squared error, simply the residuals) of the current ensemble, and added with a shrinkage factor (learning_rate). Many small corrections produce a strong model.

scikit-learn's HistGradientBoostingClassifier/Regressor bins features into histograms: fast on large data, native missing-value and categorical support, early stopping. XGBoost, LightGBM and CatBoost are popular libraries with the same idea and sklearn-compatible APIs. Key knobs: learning_rate × number of iterations, tree size (max_depth / max_leaf_nodes), regularisation, early stopping.

gradient boosting HistGradientBoosting XGBoost LightGBM learning_rate early stopping
Analogy
Boosting is a team of proof-readers in a row: the first fixes the obvious mistakes, each next one looks only at what is still wrong, and each is allowed to change only a little (learning rate) so nobody over-corrects.
How It Works — Step by Step
Step 1 / 5
  1. 1The first shallow tree makes a rough prediction.
  2. 2The next tree is trained on what is still wrong (the residuals / gradient of the loss), and its contribution is scaled by the learning rate.
  3. 3Each new tree corrects the remaining errors of the ensemble so far.
  4. 4Hundreds of small corrections add up; early stopping halts when validation error stops improving.
  5. 5Histogram-based boosting in scikit-learn (and XGBoost/LightGBM/CatBoost) is usually the strongest choice for tabular data.

What are ensemble methods? Compare bagging, boosting, voting and stacking.

Trees, Ensembles & SVM 8 min read Difficulty: Intermediate 25 of 40
Definition

Ensembles combine several models to get better accuracy or stability than any single one. Bagging trains the same model on bootstrap samples in parallel and averages (reduces variance; random forest). Boosting trains models sequentially, each correcting earlier errors (reduces bias; gradient boosting, AdaBoost). Voting combines different models by majority (hard) or by averaging probabilities (soft). Stacking trains a meta-model on out-of-fold predictions of the base models.

They work best when members are individually good and make different errors.

ensemble bagging boosting VotingClassifier StackingClassifier
Analogy
A selection panel for admissions: one interviewer can be biased; a panel vote is fairer (voting), and a chairperson who knows which interviewer is reliable for which kind of candidate is stacking.

Step 1 / 5
  1. 1Bagging trains copies of one model on different bootstrap samples and averages them, reducing variance.
  2. 2Boosting trains models sequentially, each focusing on what earlier ones got wrong, reducing bias.
  3. 3Voting combines different model types by majority or averaged probabilities.
  4. 4Stacking trains a second-level model on the base models' out-of-fold predictions.
  5. 5Diversity of errors is what makes ensembles work; weigh the gain against complexity.

What is cross-validation? Compare KFold, StratifiedKFold, GroupKFold and TimeSeriesSplit.

Model Selection, Tuning & Deployment 8 min read Difficulty: Advanced 26 of 40
Definition

k-fold cross-validation splits the training data into k folds, trains k models (each leaving one fold out) and averages the k validation scores. Every row is validated exactly once, so the estimate is less dependent on one lucky or unlucky split, and the standard deviation shows how stable the model is. cross_val_score returns one metric; cross_validate returns several metrics, fit times and (optionally) training scores.

Choose the splitter to match the data: StratifiedKFold keeps class proportions (the default for classifiers when cv is an integer); GroupKFold keeps all rows of one group (student, patient, customer) in the same fold; TimeSeriesSplit always validates on later data than it trains on. Preprocessing must sit inside a Pipeline so it is re-fitted in each fold.

cross_val_score cross_validate KFold StratifiedKFold GroupKFold TimeSeriesSplit
Analogy
One test paper can be easy or hard by chance. Cross-validation is like giving the class five different papers and averaging: the average is fairer, and the spread tells you whether the student is consistently good or just got lucky once.
How It Works — Step by Step
Step 1 / 5
  1. 1The training data is cut into 5 folds. Round 1: train on folds 2–5, validate on fold 1.
  2. 2Round 2: a different fold is held out.
  3. 3Each round trains a fresh model.
  4. 4Every row is used for validation exactly once and for training four times.
  5. 5The mean (and spread) of the 5 scores is a more reliable estimate than one split. Choose the splitter that matches the data structure.

Cross Questions
What if you scale the data before cross-validation?
The scaler has seen the validation folds: leakage, usually a small optimistic bias, and much larger for steps like feature selection or target encoding.
How many folds?

Why not shuffle time-series data?
Shuffling lets the model train on the future and validate on the past, which is impossible in production; TimeSeriesSplit avoids it.
Is the CV score the final performance estimate?
Not after you used it to choose hyperparameters; that choice makes it slightly optimistic. Use the untouched test set or nested CV.

How do you tune hyperparameters with GridSearchCV and RandomizedSearchCV?

Model Selection, Tuning & Deployment 9 min read Difficulty: Advanced 27 of 40
Definition

Hyperparameters are settings chosen before training (max_depth, C, learning_rate), unlike parameters learned from data (coefficients, split thresholds). GridSearchCV tries every combination in a grid with cross-validation; RandomizedSearchCV samples n_iter combinations from lists or distributions (e.g. loguniform), which is far cheaper when there are many parameters.

Parameters of pipeline steps are addressed as step__param (e.g. model__max_depth, pre__num__simpleimputer__strategy). After fitting, best_params_, best_score_, cv_results_ and the refitted best_estimator_ are available. Use n_jobs=-1 to parallelise; HalvingGridSearchCV or Optuna for large spaces.

Analogy
Tuning is like finding the best oven temperature and baking time. Grid search bakes a cake for every pair on a chart; random search bakes 20 cakes at random settings, which usually finds a great one with far fewer cakes when only one or two settings really matter.
How It Works — Step by Step
Step 1 / 5
  1. 1Define candidate values for each hyperparameter (step names reach inside the pipeline).
  2. 2Every combination is evaluated with cross-validation; the cell colour marks the best mean score.
  3. 3The best combination is refitted on all training data and exposed as best_estimator_.
  4. 4Random search samples combinations, usually finding good settings with far fewer fits.
  5. 5Successive halving and Bayesian tools scale further; the test set stays untouched until the end.

Cross Questions
Why is random search often better than grid search?
Usually only a few parameters matter. A grid wastes fits repeating the same values of the important parameter; random sampling tries many distinct values of each.
What is nested cross-validation?
An outer CV loop around the whole search, giving an unbiased estimate of "tune + train" performance; used when there is no separate test set.
In the example the best tree scored 0.841 in CV but 0.789 on test. Why?
Picking the maximum of 12 noisy CV scores favours a lucky configuration (selection bias), and a 150-row test set is itself noisy. The boosting model, with a smoother score, held up (0.843 → 0.845).
The best parameter is at the edge of the grid. What now?
Extend the grid in that direction; the true optimum may lie outside it.
How do you tune the decision threshold?
It is not a model hyperparameter: pick it on validation predictions for the business metric, or use TunedThresholdClassifierCV (sklearn ≥ 1.5).

How do learning curves and validation curves diagnose underfitting and overfitting?

Model Selection, Tuning & Deployment 8 min read Difficulty: Advanced 28 of 40
Definition

A learning curve (learning_curve) plots training and validation scores against the number of training rows. If both are low and close: underfitting (high bias) — more data will not help, a more flexible model will. If training is much higher than validation and validation is still rising: overfitting (high variance) — more data or regularisation helps.

A validation curve (validation_curve) varies one hyperparameter (e.g. max_depth, C) and shows where validation score peaks: to the left the model underfits, to the right it overfits. Both functions use cross-validation internally and return arrays you can plot with matplotlib or LearningCurveDisplay / ValidationCurveDisplay.

learning_curve validation_curve bias variance underfitting overfitting
Analogy
A learning curve is like tracking a student's practice and exam scores as they do more past papers. If both stay low, they need a better method, not more papers. If practice is perfect but exams lag, they are memorising answers and need varied practice.
How It Works — Step by Step
Step 1 / 5
  1. 1A learning curve plots scores against training-set size; training score starts high.
  2. 2Validation score rises with more data. When the curves converge and flatten, more data will not help much; a persistent gap suggests overfitting.
  3. 3A validation curve varies one hyperparameter: training score keeps rising with complexity.
  4. 4Validation score peaks and then falls: the peak is the best complexity.
  5. 5Both curves turn the bias-variance trade-off into something you can see and act on.

How do you measure feature importance? Compare impurity-based importance, permutation importance and feature selection.

Model Selection, Tuning & Deployment 8 min read Difficulty: Advanced 29 of 40
Definition

Tree ensembles expose feature_importances_: the total impurity decrease from splits on each feature, computed on the training data. It is fast but biased towards features with many unique values (continuous or ID-like columns), even if they are useless. Permutation importance (sklearn.inspection.permutation_importance) shuffles one column at a time on held-out data and measures how much the score drops; it works for any model.

For linear models, standardised coefficients show direction and size. Feature selection tools: SelectKBest (univariate tests), RFE/RFECV (recursive elimination), SelectFromModel (e.g. L1 or tree importances). SHAP values (separate library) explain individual predictions. Correlated features share (and can hide) importance.

Analogy
Impurity importance is asking players how much they touched the ball; permutation importance is benching one player and seeing how much the team's score drops. A busy player is not always a useful one.
How It Works — Step by Step
Step 1 / 5
  1. 1Tree models report impurity-based importances: how much each feature reduced impurity during training.
  2. 2Permutation importance shuffles one feature at a time on validation/test data and measures how much the score drops.
  3. 3Impurity importance is biased towards features with many unique values, such as IDs, and reflects training data only.
  4. 4Permutation importance works for any model and reflects real predictive value on unseen data.
  5. 5Feature selection methods and SHAP values build on these ideas.

Why can permutation importance be negative?
Shuffling a useless feature can by chance slightly improve the score; values around zero (within the std) mean "no effect".
Two features are highly correlated. What happens to their importances?
They share it: permuting one leaves the other carrying the information, so both can look unimportant though together they matter.
Does importance mean causation?
No. It measures how much the model relies on a feature, not what happens if you change it in the real world.
Should you select features before or inside cross-validation?
Inside (in the pipeline). Selecting on all data first leaks information and inflates scores.

How does K-Means clustering work? How do you choose k with the elbow method and silhouette score?

Unsupervised Learning & Text 9 min read Difficulty: Advanced 31 of 40
Definition

K-Means partitions rows into k clusters. It places k centroids, assigns every point to the nearest centroid, moves each centroid to the mean of its points, and repeats until assignments stop changing. It minimises inertia (the within-cluster sum of squared distances). n_init restarts with different seeds and keeps the best; k-means++ initialisation spreads the starting centroids.

Choosing k: the elbow method (inertia keeps falling as k grows; look for the bend) and the silhouette score (−1…1: how much closer each point is to its own cluster than to the next one; higher is better). K-Means uses distances, so scale features, and it assumes round, similar-sized clusters. Clusters must be interpreted by profiling them.

KMeans centroid inertia elbow method silhouette_score k-means++
Analogy
Placing k bus stops in a town: start with rough spots, let every resident walk to the nearest stop, move each stop to the middle of its riders, and repeat until nobody switches stop.
How It Works — Step by Step
Step 1 / 5
  1. 1Start with k centroids (✕). k-means++ spreads them out; here k = 3.
  2. 2Assign every student to the nearest centroid (Euclidean distance on scaled features).
  3. 3Move each centroid to the mean of the points assigned to it.
  4. 4Repeat assign + move until nothing changes. Compare inertia and silhouette across k: k = 2 and 3 are almost tied; the elbow and usefulness favour 3.
  5. 5Profile the clusters in original units. The placement rate (not used for clustering) confirms the segments are meaningful.
Real-World Scenario
Student segments for mentoring

The centre clusters students on attendance, study hours and mock-test score. Profiling the clusters gives named segments such as "engaged high performers" and "low attendance, low effort", each with its own mentoring plan. The placement label is not used to build the clusters, only afterwards to check that the segments are meaningful.

Cross Questions
In the example, silhouette is slightly higher for k=2 (0.307) than k=3 (0.303). Why choose 3?
The difference is tiny, the elbow bends around 3, and three segments map to three distinct mentoring plans. Metrics guide the choice; usefulness decides it.
Why must features be scaled for K-Means?
It uses Euclidean distance; a feature measured in larger units (attendance 0–100) would dominate one in smaller units (study hours 0–15).
Does K-Means always find the same clusters?

Non-spherical shapes (moons, rings), very different cluster sizes or densities, and outliers, which pull centroids. Use DBSCAN or Gaussian mixtures instead.
How do you cluster categorical data?
One-hot encode carefully, or use K-Modes / K-Prototypes (separate library), or Gower distance with hierarchical clustering.

Explain hierarchical clustering and DBSCAN. When are they better than K-Means?

Unsupervised Learning & Text 8 min read Difficulty: Advanced 32 of 40
Definition

Agglomerative (hierarchical) clustering starts with every point as its own cluster and repeatedly merges the two closest clusters; the merge history is a dendrogram you can cut at any level. Linkage defines "closest": ward (minimise variance, default), complete, average, single (nearest points, can follow chains).

DBSCAN groups points that have at least min_samples neighbours within radius eps (core points) and expands clusters through connected core points; points in sparse regions are labelled noise (−1). It finds arbitrary shapes and does not need k, but eps must suit the data scale and it struggles with clusters of very different density (HDBSCAN helps).

AgglomerativeClustering dendrogram linkage DBSCAN eps min_samples noise
Analogy
Hierarchical clustering is a family tree built bottom-up: individuals, then siblings, then cousins. DBSCAN is finding crowds at a fair: people standing close together form a crowd however oddly shaped, and lone wanderers are nobody's crowd.
How It Works — Step by Step
Step 1 / 5
  1. 1K-Means splits the plane with a straight boundary between centroids, so it cuts each moon in half.
  2. 2DBSCAN looks at the neighbourhood of each point: a point with at least min_samples neighbours within eps is a core point.
  3. 3Clusters grow through connected core points, following any shape; isolated points become noise (−1).
  4. 4Agglomerative clustering merges the closest clusters step by step; cutting the dendrogram at a height gives the clusters.
  5. 5Real results on 300 moon points: single linkage and DBSCAN recover the moons perfectly, but DBSCAN is very sensitive to eps.
Real-World Scenario
Spotting odd groups and loners

Clustering login locations or lab-usage patterns: DBSCAN finds dense, oddly shaped hot spots and marks isolated sessions as noise, which is exactly what the IT team wants to review. A dendrogram of courses by syllabus similarity lets the academic team choose how many groups to merge.

What is PCA? How do you choose the number of components and when should you use it?

Unsupervised Learning & Text 9 min read Difficulty: Advanced 33 of 40
Definition

Principal Component Analysis finds new axes (principal components) that are linear combinations of the original features, ordered by how much variance they capture, and mutually uncorrelated. Projecting onto the first few components keeps most of the information in fewer columns. explained_variance_ratio_ gives each component's share; components_ holds the loadings (weights).

Uses: visualising high-dimensional data in 2-D, removing correlated/noisy features, speeding up models, compression. Always standardise first (PCA is variance-based). PCA(n_components=0.95) keeps enough components for 95 % of the variance. Costs: components are harder to interpret, and PCA is unsupervised, so it can discard directions that matter for the target.

PCA explained_variance_ratio_ components_ dimensionality reduction loadings t-SNE/UMAP
Analogy
PCA is choosing the best camera angle for a 3-D sculpture: from one angle the photo shows almost all the shape, from another it is a flat line. PCA finds the angles that show the most spread.
How It Works — Step by Step
Step 1 / 5
  1. 1Correlated, standardised features form an elongated cloud.
  2. 2PC1 points along the direction of greatest spread; PC2 is perpendicular to it and captures the next-largest spread.
  3. 3Projecting each point onto PC1 keeps most of the information in one number instead of two.
  4. 4On the 13-feature wine data the first two components hold 55 % of the variance; the cumulative share tells you how many to keep.
  5. 5Two components already give 0.955 CV accuracy versus 0.983 with all features: much simpler, slightly less accurate.
Real-World Scenario
Visualising 13 lab measurements

A food lab measures 13 chemical properties of wine samples. Projecting onto two principal components produces a scatter plot where the three cultivars separate clearly, and a classifier on just 2 components loses very little accuracy compared with all 13.

Is PCA feature selection?
No; it creates new features (combinations of all originals). Feature selection keeps a subset of the original columns.
Why standardise before PCA?

PCA vs t-SNE/UMAP?

Can PCA hurt a model?

How do you detect anomalies with Isolation Forest and Local Outlier Factor?

Unsupervised Learning & Text 8 min read Difficulty: Advanced 34 of 40
Definition

Isolation Forest builds random trees that split on random features at random thresholds. Anomalies are few and different, so they are isolated in fewer splits (short average path length). decision_function gives a score (lower = more abnormal); predict returns −1 for anomalies and 1 for normal points, based on contamination (the expected share of anomalies).

Local Outlier Factor (LOF) compares a point's local density with that of its neighbours; much lower density means outlier. Other options: One-Class SVM, z-scores/IQR for single features, EllipticEnvelope for Gaussian data. Anomaly detection is mostly unsupervised, so results need review by someone who knows the domain.

IsolationForest LocalOutlierFactor contamination decision_function outliers
Analogy
Playing "Guess who?": an ordinary person needs many questions to be singled out, but someone with a top hat, a parrot and a cape is identified in two questions. Isolation Forest counts the questions.
How It Works — Step by Step
Step 1 / 5
  1. 1Most students form a dense cloud; one record is far from it.
  2. 2Random splits on random features isolate the odd record after only two cuts.
  3. 3A typical student sits among many others, so many cuts are needed to isolate it.
  4. 4Averaging the path length over many random trees gives an anomaly score: lower is more abnormal. The five planted records rank near the top.
  5. 5contamination=0.02 flags the 12 lowest-scoring rows; the list goes to a person for review, not to automatic action.

Catching suspicious records

How do you classify text with scikit-learn? Explain bag-of-words, TF-IDF and Naive Bayes.

Unsupervised Learning & Text 9 min read Difficulty: Advanced 35 of 40
Definition

Models need numbers, so text is vectorised. Bag-of-words (CountVectorizer) counts how often each vocabulary word appears, ignoring order. TF-IDF (TfidfVectorizer) multiplies term frequency by inverse document frequency, so words that appear in every document ("the", "and") get low weight and distinctive words get high weight. Options: ngram_range=(1, 2), stop_words="english", min_df, max_features. The result is a sparse matrix.

Multinomial Naive Bayes is a fast, strong baseline for word counts: it assumes words are independent given the class and multiplies per-class word probabilities. Linear models (LogisticRegression, LinearSVC) on TF-IDF are often a little more accurate. For meaning beyond words, use embeddings or transformer models (outside scikit-learn).

TfidfVectorizer CountVectorizer MultinomialNB n-grams sparse matrix stop words
Analogy
TF-IDF is a highlighter: words every comment uses ("the", "and") barely get colour, while words that appear often in a few comments ("hadoop", "interview") are highlighted, because they tell you what the comment is about.
How It Works — Step by Step
Step 1 / 5
  1. 1Each training comment is raw text with a topic label. This one mixes a faculty phrase with a placement phrase.
  2. 2The vectoriser splits text into tokens, lowercases them and removes stop words ("are", "too", "and").
  3. 3TF-IDF turns the comment into a sparse row: one column per vocabulary word, weighted by frequency × rarity.
  4. 4Naive Bayes combines per-topic word probabilities and picks the most probable topic.
  5. 5Both models reach about 85–87 % on mixed comments; words never seen in training contribute nothing.

Cross Questions
Why fit the vectoriser only on training data?

What happens to words never seen in training?

Logistic regression and the forest are within 0.01 AUC here. Which do you deploy?

Why is the baseline AUC exactly 0.5?

Steps to Debug a Too-Good Model
  1. Be suspicious
    Compare with the baseline and with what domain experts expect.
  2. Inspect importances
    One feature dominating is a red flag.
  3. Single-feature AUC
    Any column that alone predicts nearly perfectly needs an explanation.
  4. Ask "when is it known?"
    Drop anything recorded at or after the outcome.
  5. Check duplicates and groups
    Use GroupKFold / time splits; re-evaluate.
Cross Questions
Why do duplicates inflate scores even without a leaky feature?
A near-copy of a test row sits in training, so a flexible model like a forest can recall its label rather than generalise.
What is train/serve skew?
Features computed differently in training and in production (e.g. averages over different windows). The model looks good offline and fails live; shared pipelines prevent it.
How do you prevent leakage organisationally?
Document for each feature the time it becomes available, build training sets "as of" the prediction date, and review features with domain experts.

Scenario: the deployed model scores new batches every month. How do you detect drift and decide when to retrain?

Scenario-Based Questions 9 min read Difficulty: Expert 40 of 40
Definition

Data drift: the distribution of inputs changes (new batches have lower mock scores, a new centre opens). Concept drift: the relationship between inputs and outcome changes (the job market shifts, so the same scores lead to fewer placements). Both degrade a model silently because it still returns confident predictions.

Monitor: input statistics per feature (mean shift in standard deviations, PSI — Population Stability Index; PSI < 0.1 stable, 0.1–0.25 moderate, > 0.25 significant), the share of unknown categories, the distribution of predicted probabilities, and, once labels arrive, real performance. Retrain on recent data when drift is significant or performance falls, then compare the new model with the old one before switching.

Analogy
A model is a map. Data drift is driving into a new suburb the map barely covers; concept drift is when the roads themselves have been rebuilt. Either way, the sat-nav keeps giving confident directions, so you need signs that tell you the map is out of date.

model = Pipeline([('pre', pre), ('model', LogisticRegression())]).fit(X_train, y_train)

def psi(ref, new, bins=10):
    edges = np.unique(np.quantile(ref.dropna(), np.linspace(0, 1, bins + 1)))
    edges[0], edges[-1] = -np.inf, np.inf
    r = np.histogram(ref.dropna(), edges)[0] / ref.notna().sum()
    n = np.histogram(new.dropna(), edges)[0] / new.notna().sum()
    r, n = np.clip(r, 1e-4, None), np.clip(n, 1e-4, None)
    return float(((n - r) * np.log(n / r)).sum())

rng = np.random.default_rng(5)
months = {'Jan (like training)': (0, 0.0), 'Mar (weaker mocks)': (-6, 0.0), 'Jun (mocks + market)': (-12, -1.5)}
for month, (shift, market) in months.items():
    batch = X_test.sample(2000, replace=True, random_state=len(month))
    batch['mock_test'] = (batch['mock_test'] + shift).clip(0, 100)
    # outcome generated with the true rule; "market" lowers placement chances for everyone (concept drift)
    z = (-13 + 0.07 * batch['attendance'] + 0.18 * batch['study_hours'] + 0.08 * batch['mock_test'].fillna(65)
         + np.where(batch['course'] == 'PG-DBDA', 0.6, 0) + market)
    y_true = (rng.random(len(batch)) < 1 / (1 + np.exp(-z))).astype(int)
    p = model.predict_proba(batch)[:, 1]
    drift = {c: round(psi(X_train[c], batch[c]), 3) for c in num}

Cross Questions
In June the AUC is still fine but the predicted placement rate is far above the actual one. What happened?
Concept drift: ranking still works (AUC), but the overall level shifted, so probabilities are miscalibrated. Recalibrating or retraining on recent outcomes fixes the level.
Why can drift be detected before labels arrive?
Input and prediction distributions are available immediately; outcomes (placements) may take months.
How often should you retrain?
On a schedule matched to how fast the domain changes, plus on alerts; always validate the new model against the current one first.
What is PSI's weakness?
It depends on binning and sample size and looks at one feature at a time; combine it with performance monitoring.
