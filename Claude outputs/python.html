What is Python? What are its key features?

Definition

Python is a high-level, general-purpose, interpreted programming language created by Guido van Rossum and first released in 1991. It emphasises readable code — indentation is part of the syntax — and supports procedural, object-oriented and functional styles.

Cross Questions
Is Python compiled or interpreted?
Both, in a sense. CPython first compiles source code to bytecode (.pyc), then the Python Virtual Machine interprets that bytecode. It is called interpreted because there is no separate ahead-of-time compile step producing machine code.
What are the disadvantages of Python?
Slower than C/Java for CPU-bound code, the GIL limits multi-threaded CPU work, higher memory use, and runtime type errors. In data engineering this is mitigated because heavy work runs inside optimised engines (NumPy, Spark, databases).
Python 2 vs Python 3?
Python 2 reached end of life in January 2020. Key Python 3 differences: print() is a function, strings are Unicode by default, / is true division (3/2 = 1.5), and range is lazy.

What is dynamic typing? How do variables work in Python?

Python Basics 6 min read Difficulty: Beginner 3 of 65
Definition

In Python a variable is a name that refers to an object. The object has a type; the name does not. The same name can later refer to an object of a different type — this is dynamic typing.

Assignment never copies data: b = a makes b refer to the same object as a.

Mental model: Think of variables as labels (sticky notes) attached to objects, not as boxes that contain values.
Dynamic Typing Names References id() type() Strong Typing
How It Works — Step by Step
Step 1 / 4
  1. 1a = [1, 2, 3] creates a list object and binds the name a to it. The name is a label, not a box holding the list.
  2. 2b = a copies nothing. It attaches a second label to the same object, so a is b is True.
  3. 3b.append(4) mutates that one shared object, so printing a also shows 4.
  4. 4c = list(a) builds a new list object. Changing c no longer affects a.

Cross Questions
What is the difference between dynamic and static typing?
Static typing (Java, C) checks types at compile time and variables have fixed declared types. Dynamic typing (Python) checks types at runtime, so type errors appear only when that line runs. Type hints + tools like mypy add optional static checking.
What does id() return?
A unique integer identifying the object during its lifetime. In CPython it is the object's memory address. Two names with the same id refer to the same object.
Python is dynamically typed — is it also weakly typed?
No. Python is dynamically but strongly typed: it does not silently convert between unrelated types ("5" + 5 fails). JavaScript, in contrast, is weakly typed ("5" + 5 = "55").

Why It Matters

Why it matters:

  • Dictionary keys and set elements must be hashable — in practice, immutable. A tuple can be a dict key; a list cannot.
  • Shared references: passing a list to a function lets the function modify the caller's list.

How does a Python dictionary work internally?

Data Structures 8 min read Difficulty: Basic 10 of 65
Definition

A dictionary stores key → value pairs and gives average O(1) lookup, insert and delete. Internally it is a hash table: Python computes hash(key), uses it to pick a slot, and stores the key, value and hash there.

Since Python 3.7, dictionaries are guaranteed to preserve insertion order.

dict Hash Table hash() Collision O(1) Insertion Order
How It Works — Step by Step
Step 1 / 6
  1. 1We store the key 'city' with the value 'Pune'.
  2. 2Python computes hash('city'), a large integer derived from the key's content. Equal keys always produce equal hashes.
  3. 3The hash is reduced to an index into the internal table (conceptually hash % table_size), here slot 5.
  4. 4The key, value and hash are stored in that slot. No searching through other entries was needed.
  5. 5A lookup repeats the same calculation, jumps straight to slot 5, confirms the stored key equals 'city' and returns the value. That is average O(1) however big the dict is.
  6. 6If two keys land in the same slot (a collision), Python probes other slots. This is why keys must be hashable (immutable): a key whose hash changed after insertion could never be found again.
Detailed Explanation
  • Keys must be hashable (immutable): str, int, tuple of immutables. Lists/dicts cannot be keys.
  • Collisions (two keys mapping to the same slot) are resolved by open addressing — probing other slots. Equal keys must have equal hashes, which is why __eq__ and __hash__ must agree.
  • The table is resized (roughly doubled) when about two-thirds full, so occasional inserts cost O(n), but average stays O(1).
  • Modern CPython uses a compact layout: a small index array plus a dense entries array — that is what keeps insertion order.

What happens if two keys have the same hash?
That is a collision. Python probes for another slot; on lookup it compares both the hash and the key with ==, so the right value is still found. Many collisions degrade performance toward O(n).
Why can't a list be a dictionary key?
Lists are mutable — if the list changed after insertion, its hash would change and the entry could never be found again. So lists are unhashable.

What is the difference between a shallow copy and a deep copy?

Data Structures 6 min read Difficulty: Basic 13 of 65
Definition

Assignment (b = a) copies nothing — both names point to the same object.

A shallow copy creates a new outer object but shares the inner objects.

A deep copy recursively copies the outer object and everything inside it.

copy deepcopy Shallow Copy Nested Objects Aliasing
How It Works — Step by Step
Step 1 / 4
  1. 1orig is a dict whose "skills" value is a list, a separate inner object.
  2. 2copy.copy(orig) (a shallow copy) creates a new outer dict, but its "skills" entry points to the same inner list.
  3. 3copy.deepcopy(orig) recursively copies everything: a new dict and a new inner list.

What is the mutable default argument problem?

Functions 5 min read Difficulty: Intermediate 17 of 65
Definition

Default argument values are evaluated once, when the function is defined — not each time it is called. If the default is a mutable object (list, dict, set), every call that uses the default shares the same object, and changes accumulate between calls.

Default Arguments Mutable None Sentinel Gotcha
How It Works — Step by Step
Step 1 / 4
  1. 1When Python executes the def statement it evaluates the default [] once and stores that list object on the function (add_record.__defaults__).
  2. 2The first call uses the default and appends "r1" to that stored list.
  3. 3The second call uses the same list object, which already holds "r1", so the result is ['r1', 'r2']. State leaks between calls.
  4. 4Fix: use None as the default and create a fresh list inside the function on each call.

def add_record_fixed(record, batch=None):
    if batch is None:                    # create a new list on each call
        batch = []
    batch.append(record)
    return batch

print(add_record_fixed("r1"))
print(add_record_fixed("r2"))
print(add_record.__defaults__)           # the shared default lives here

import functools, time

def retry(times=3, delay=0.01, exceptions=(Exception,)):    # decorator WITH arguments
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            for attempt in range(1, times + 1):
                try:
                    return func(*args, **kwargs)
                except exceptions as e:
                    print(f"attempt {attempt} failed: {e}")
                    if attempt == times:
                        raise
                    time.sleep(delay)
        return wrapper
    return decorator

calls = {"n": 0}

@retry(times=3, exceptions=(ConnectionError,))
def fetch_page():
    calls["n"] += 1
    if calls["n"] < 3:
        raise ConnectionError("API timeout")
    return {"status": 200}

attempt 2 failed: API timeout
{'status': 200}
Key Points
  • functools.wraps copies __name__, __doc__ etc. from the original — without it, every decorated function looks like "wrapper" in logs.
  • Decorator with arguments = three levels: retry(times) → decorator(func) → wrapper(*args).
  • Built-in decorators: @staticmethod, @classmethod, @property, @functools.lru_cache, @dataclass.
  • Stacking: @a @b def f means f = a(b(f)) — the one closest to the function is applied first.
  • Airflow uses decorators in the TaskFlow API: @dag, @task.

What are generators and the yield keyword? Why are they memory-efficient?

Definition

A generator function contains yield. Calling it does not run the body — it returns a generator (a kind of iterator). Each next() runs the code until the next yield, hands out that value, and pauses with all local state saved.

Because values are produced lazily, one at a time, a generator can process data far larger than memory — millions of lines, an endless stream, or paginated API results.

Generator yield Lazy Evaluation yield from Memory Efficient Pipeline
How It Works — Step by Step
Step 1 / 5
  1. 1Calling countdown(3) does not execute its body. It returns a generator object, paused before the first line.
  2. 2The first next(g) runs the body until it reaches yield n. The value 3 is handed to the caller and the generator pauses, keeping its local variables.
  3. 3The next next(g) resumes right after the yield, decrements n, loops and yields 2. No state is lost between calls.
  4. 4When the function body finishes, the generator raises StopIteration. A for loop handles this for you and simply ends.
  5. 5Because values are produced one at a time on demand, a generator can process a 50 GB file line by line with almost no memory.

    "INFO start\nERROR db timeout\nINFO rows=10\nERROR api 503\nWARN slow\n")

    with open(path) as f:
        for line in f:
            yield line.rstrip("\n")

    for line in lines:
        if line.startswith("ERROR"):
            yield line

def parse(lines):
    for line in lines:
        level, *msg = line.split(" ", 1)

How does Python manage memory? Explain reference counting and garbage collection

Definition

CPython manages memory automatically using two mechanisms:

  • Reference counting — every object tracks how many references point to it. When the count drops to zero, the object is freed immediately.
  • Cyclic garbage collector — finds groups of objects that reference each other (cycles) but are no longer reachable, which reference counting alone can never free. It is generational (generations 0, 1, 2): young objects are checked most often.

All objects live on a private heap managed by Python; small objects use a fast allocator called pymalloc.

Objects kept alive unintentionally: growing global lists/caches, closures holding big objects, unbounded lru_cache, and reference cycles involving objects with __del__ in old code. Tools: tracemalloc, objgraph, memory_profiler.

Freed memory often goes back to Python's own allocator pools for reuse rather than to the OS, so the process size can stay high even after objects are freed.

What is the GIL (Global Interpreter Lock)?

Definition

The Global Interpreter Lock is a mutex in CPython that allows only one thread to execute Python bytecode at a time, even on a multi-core machine. It exists mainly because reference counting is not thread-safe without it.

How It Works — Step by Step
Step 1 / 4
  1. 1Two threads run pure-Python, CPU-heavy work. In CPython only the thread holding the GIL can execute bytecode.
  2. 2So the threads take turns (the interpreter switches every few milliseconds). Total time is about the same as running them one after the other, and sometimes worse.
  3. 3Now each thread mostly waits for an API or database. While waiting on I/O, a thread releases the GIL, so the other thread can run.
  4. 4The waiting periods overlap, so threads (or asyncio) give a real speed-up for I/O-bound work. For CPU-bound work use multiprocessing: separate processes each have their own interpreter and GIL.

Definition

import os
import requests
from requests.adapters import HTTPAdapter
from urllib3.util.retry import Retry

def make_session(token):
    session = requests.Session()
    retry = Retry(total=5, backoff_factor=1,                  # waits 1, 2, 4, 8 … seconds
                  status_forcelist=[429, 500, 502, 503, 504],
                  allowed_methods=["GET"])
    session.mount("https://", HTTPAdapter(max_retries=retry))
    session.headers.update({"Authorization": f"Bearer {token}"})
    return session

def fetch_all(session, url, page_size=100):
    """Yield records from a page-number paginated API."""
    page = 1
    while True:
        resp = session.get(url, params={"page": page, "per_page": page_size}, timeout=30)
        resp.raise_for_status()                               # raise for 4xx/5xx
        records = resp.json()["data"]
        if not records:
            break
        yield from records
        page += 1

def fetch_all_cursor(session, url):
    """Cursor-based pagination: the API returns the next cursor."""
    params = {}
    while True:
        body = session.get(url, params=params, timeout=30).json()
        yield from body["items"]
        if not body.get("next_cursor"):
            break
        params["cursor"] = body["next_cursor"]

session = make_session(token=os.environ["API_TOKEN"])
# batches() is the helper from question 37; load_to_staging() writes to your DB
for batch in batches(fetch_all(session, "https://api.example.com/v1/orders"), 1000):
    load_to_staging(batch)                                    # write in batches

After each failure wait longer (1s, 2s, 4s, 8s …) plus a small random amount, so many clients do not retry at the same instant and overload the server again.

Approach
  • Pythonic: keep only alphanumeric characters in lower case, compare with its reverse s[::-1].
  • Interview follow-up (O(1) extra space): two pointers from both ends, skipping non-alphanumerics.
Complexity: Both O(n) time. Slicing uses O(n) extra space; two pointers use O(1).
Solution
Python
def is_palindrome(s: str) -> bool:
    cleaned = [c.lower() for c in s if c.isalnum()]
    return cleaned == cleaned[::-1]

def is_palindrome_two_pointers(s: str) -> bool:
    i, j = 0, len(s) - 1
    while i < j:
        if not s[i].isalnum():
            i += 1
        elif not s[j].isalnum():
            j -= 1
        elif s[i].lower() != s[j].lower():
            return False
        else:
            i += 1; j -= 1
    return True

for text in ["Madam", "A man, a plan, a canal: Panama", "data", ""]:
    print(repr(text), is_palindrome(text), is_palindrome_two_pointers(text))

Problem

How It Works — Step by Step
Step 1 / 4
  1. 1Look at 2. To reach 9 we need 7. The dict seen is empty, so store 2 with its index 0.
  2. 2Look at 11. We need −2, which has not been seen, so store 11 → 1.
  3. 3Look at 7. We need 2, and 2 is in seen at index 0. Dict lookup is O(1), so no inner loop is needed.
  4. 4Return (0, 2). A single pass makes it O(n) time with O(n) extra memory, instead of the O(n²) nested-loop brute force.
Approach
  • Brute force checks every pair — O(n²).
  • Optimal: one pass with a dict mapping value → index. For each number, check whether target − number has already been seen.
Complexity: O(n) time, O(n) space.
Solution
Python
def two_sum(nums, target):
    seen = {}                               # value -> index
    for i, n in enumerate(nums):
        need = target - n
        if need in seen:
            return seen[need], i
        seen[n] = i
    return None

print(two_sum([2, 7, 11, 15], 9))
print(two_sum([3, 2, 4], 6))
print(two_sum([1, 2], 10))

def flatten(items):
    for x in items:
        if isinstance(x, (list, tuple)):
            yield from flatten(x)

def flatten_iterative(items):
    stack, out = [iter(items)], []
    while stack:
        for x in stack[-1]:
            if isinstance(x, (list, tuple)):
                stack.append(iter(x))
                break
            out.append(x)
        else:
            stack.pop()
    return out

Problem

Given a string containing ()[]{}, determine whether every opening bracket is closed by the same type in the correct order.

  • "{[()]}" → True
  • "([)]" → False
  • "((" → False
How It Works — Step by Step
Step 1 / 7
  1. 1{ is an opening bracket, so push it onto the stack.
  2. 2[ is opening, so push.
  3. 3( is opening, so push. The top of the stack is always the most recent unclosed bracket.
  4. 4) closes. The top of the stack is (, a matching pair, so pop it.
  5. 5] matches the new top [, so pop.
  6. 6} matches {, so pop.
  7. 7The string is finished and the stack is empty, so the brackets are balanced. A mismatch at any point (for example ([)]) or brackets left on the stack means unbalanced. O(n) time.
Approach
  • Use a stack (a Python list).
  • Push opening brackets; on a closing bracket, the top of the stack must be the matching opener.
  • At the end the stack must be empty.
Complexity: O(n) time, O(n) space.
Solution
Python
def is_balanced(s: str) -> bool:
    pairs = {")": "(", "]": "[", "}": "{"}
    stack = []
    for ch in s:
        if ch in "([{":
            stack.append(ch)
        elif ch in pairs:
            if not stack or stack.pop() != pairs[ch]:
                return False
    return not stack

for s in ["{[()]}", "([)]", "((", "SELECT (a + (b * c))", ""]:

A CDC feed or incremental extract delivers multiple versions of the same record. Keep only the most recent version of each customer_id based on updated_at, and drop records marked as deleted.

Approach
  • Iterate once, storing the latest record per key in a dict; replace only when the new record is newer.
  • Then filter out tombstones (op == "D").
  • This is the Python version of SQL ROW_NUMBER() OVER (PARTITION BY id ORDER BY updated_at DESC) = 1, a pattern used in almost every pipeline.
Complexity: O(n) time, O(k) memory for k distinct keys.
Solution
Python
from datetime import datetime

events = [
    {"customer_id": "C1", "city": "Pune",   "op": "I", "updated_at": "2026-10-01T10:00:00"},
    {"customer_id": "C2", "city": "Delhi",  "op": "I", "updated_at": "2026-10-01T11:00:00"},
    {"customer_id": "C1", "city": "Mumbai", "op": "U", "updated_at": "2026-10-05T09:30:00"},
    {"customer_id": "C1", "city": "Nagpur", "op": "U", "updated_at": "2026-10-03T08:00:00"},  # late, older
    {"customer_id": "C3", "city": "Agra",   "op": "I", "updated_at": "2026-10-02T12:00:00"},
    {"customer_id": "C3", "city": "Agra",   "op": "D", "updated_at": "2026-10-06T12:00:00"},
]

def latest_per_key(records, key="customer_id", ts="updated_at"):
    latest = {}
    for r in records:
        r_ts = datetime.fromisoformat(r[ts])
        current = latest.get(r[key])
        if current is None or r_ts > datetime.fromisoformat(current[ts]):
            latest[r[key]] = r
    return [r for r in latest.values() if r["op"] != "D"]

for r in sorted(latest_per_key(events), key=lambda r: r["customer_id"]):
    print(r["customer_id"], r["city"], r["updated_at"])

C2 Delhi 2026-10-01T11:00:00
pandas version
import pandas as pd

df = pd.DataFrame([
    ("C1", "Pune",   "I", "2026-10-01 10:00"), ("C1", "Mumbai", "U", "2026-10-05 09:30"),
    ("C1", "Nagpur", "U", "2026-10-03 08:00"), ("C2", "Delhi",  "I", "2026-10-01 11:00"),
    ("C3", "Agra",   "D", "2026-10-06 12:00"),
], columns=["customer_id", "city", "op", "updated_at"])
df["updated_at"] = pd.to_datetime(df["updated_at"])

latest = (df.sort_values("updated_at")
            .drop_duplicates("customer_id", keep="last")
            .query("op != 'D'")
            .sort_values("customer_id"))
print(latest.to_string(index=False))

         C1 Mumbai  U 2026-10-05 09:30:00
         C2  Delhi  I 2026-10-01 11:00:00
Cross Questions
What if two versions have exactly the same timestamp?
Define a deterministic tie-breaker — a sequence number or log position (binlog offset, Kafka offset) from the source — otherwise results can differ between runs.
How is this done in PySpark?
Window.partitionBy("customer_id").orderBy(col("updated_at").desc()) with row_number(), filter rn == 1; or a MERGE INTO on Delta Lake to upsert the latest version.
