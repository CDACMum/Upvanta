What is Linux? What are the kernel, shell and distribution? Why is Linux used for big data?

Linux Foundations 7 min read Difficulty: Beginner 1 of 40
Definition

Linux is an open-source, Unix-like operating system. Strictly, Linux is the kernel: the core that manages processes, memory, files, devices and networking. A shell (bash, zsh) is the command interpreter users type into; together with GNU tools it forms the user environment. A distribution (Ubuntu, RHEL, Rocky, Debian, Amazon Linux) packages the kernel, tools, a package manager and defaults.

Big data runs on Linux because servers and clusters run Linux: it is free, stable, scriptable, multi-user, secure, and Hadoop, Spark, Kafka, Hive and cloud VMs are built and tested on it.

Linux kernel shell bash distribution Ubuntu
Analogy
The kernel is a building's electricity, plumbing and lifts; the shell is the reception desk where you ask for things; a distribution is a furnished building from a particular builder: same foundations, different fittings.
How It Works — Step by Step
Step 1 / 5
  1. 1At the bottom is the hardware.
  2. 2The kernel manages it: scheduling processes, memory, file systems, devices and networking. Strictly, "Linux" is this kernel.
  3. 3The shell and command-line tools let users talk to the kernel; each command becomes system calls.
  4. 4Applications, including the whole big-data stack, run on top. Almost all servers and clusters run Linux.
  5. 5A distribution packages the kernel with tools, a package manager and defaults.
Real-World Scenario
A PG-DBDA lab day

You SSH into a lab server, start HDFS and YARN with shell scripts, submit Spark jobs from the terminal, read logs with tail and grep, and schedule a nightly ingest with cron. Interviews for data-engineering roles always include Linux questions for this reason.

Cross Questions
Linux vs Unix?
Unix is the original OS family (AT&T, 1970s) and a trademark/specification; Linux is an independent Unix-like kernel that follows similar design and POSIX standards.
What is a shell vs a terminal?
The terminal is the window/program that shows text; the shell (bash) is the program inside it that reads and runs commands.
Ubuntu vs RHEL family?
Ubuntu/Debian use .deb packages and apt; RHEL/Rocky/CentOS use .rpm packages and dnf/yum. Commands and concepts are otherwise mostly the same.

Explain the Linux filesystem hierarchy. What is the difference between absolute and relative paths?

Linux Foundations 7 min read Difficulty: Beginner 2 of 40
Definition

Linux has a single directory tree starting at / (root). Standard locations (FHS): /home users' files, /root root's home, /etc configuration, /var variable data (/var/log logs), /tmp temporary files, /usr/bin programs, /opt optional software, /dev devices, /proc kernel/process information, /mnt and /media mount points.

An absolute path starts with / and is the same from anywhere. A relative path is interpreted from the current directory. Shortcuts: ~ home, . current, .. parent, - (in cd) previous directory.

FHS /etc /var/log absolute path relative path pwd
Analogy
An absolute path is a full postal address ("India, Maharashtra, Navi Mumbai, Kharghar, C-DAC"); a relative path is directions from where you stand ("next building on the left").
How It Works — Step by Step
Step 1 / 5
  1. 1Everything hangs off a single root directory, /.
  2. 2Users work in /home; configuration lives in /etc; logs in /var/log; /tmp is shared scratch space.
  3. 3Programs are in /usr/bin; big-data software is often unpacked into /opt; /proc and /dev expose the kernel and devices as files.
  4. 4Absolute paths start with /; relative paths start from the current directory. ~, . and .. are shortcuts.
  5. 5Extra disks are mounted into the tree, so there are no drive letters.
Real-World Scenario
Where things live on a Hadoop node

Hadoop unpacked in /opt/hadoop, its configuration in /opt/hadoop/etc/hadoop (or /etc/hadoop/conf), logs in /var/log/hadoop or $HADOOP_HOME/logs, data directories on mounted disks like /data1, and your scripts in /home/student. Knowing the layout tells you where to look when something breaks.

    pwd.

Cross Questions
What is in /proc?
A virtual filesystem generated by the kernel: /proc/cpuinfo, /proc/meminfo, and a directory per running process (/proc/<pid>).
Why does a script work from the terminal but fail in cron?
Often relative paths or a different PATH/working directory; use absolute paths and set PATH in the script.
What is a mount point?
A directory where another filesystem (disk partition, NFS share, USB drive) is attached to the tree.

What are the basic commands to create, copy, move, rename and delete files and directories?

Linux Foundations 7 min read Difficulty: Beginner 3 of 40
Definition

ls list (-l long, -a hidden, -h human sizes, -t by time, -R recursive); mkdir (-p parents); touch create empty file / update timestamp; cp copy (-r directories, -p keep attributes, -i confirm); mv move or rename; rm delete (-r recursive, -f force, -i confirm); rmdir remove an empty directory; tree show a directory tree.

There is no recycle bin: rm is permanent.

ls mkdir cp mv rm touch
Analogy
Working with folders in a filing cabinet: make a new folder (mkdir), photocopy a document (cp), move it to another drawer or relabel it (mv), and shred it (rm), and a shredder has no undo.
How It Works — Step by Step
Step 1 / 5
  1. 1A typical session: create a project folder structure, copy, move, delete and list.
  2. 2mkdir -p creates nested directories in one go; brace expansion makes several at once.
  3. 3cp -r copies directories; mv both moves and renames.
  4. 4rm deletes permanently; there is no recycle bin on the command line.
  5. 5ls -la shows permissions, owner, size, date and hidden files (names starting with a dot).
Real-World Scenario
Setting up a project workspace

Every new batch project starts with mkdir -p project/{data/raw,data/clean,scripts,logs}, raw files copied in with cp, processed outputs moved with mv into dated folders, and old logs removed. Doing it from the shell is repeatable and scriptable.

  1. Create the structure
    mkdir -p with brace expansion.
  2. Copy safely
    cp -i (or -n no-clobber) to avoid overwriting.

Why did rmdir project/data fail?
rmdir only removes empty directories; data still contained raw/ and clean/. rm -r removes recursively.
How do you recover a file deleted with rm?

cp vs mv within the same filesystem?

How do you view file contents? Explain cat, less, head, tail, tail -f and wc.

Linux Foundations 6 min read Difficulty: Beginner 4 of 40
Definition

cat prints whole files (or concatenates several); less pages through large files (search with /, quit with q); head -n N / tail -n N show the first/last N lines; tail -n +2 starts from line 2 (skip a header); tail -f follows a growing file; wc -l counts lines; nl numbers lines; file identifies the type; stat shows metadata.

cat less head tail tail -f wc
Analogy
head reads the first page of a register, tail the last page, less lets you flip through it, and tail -f is standing next to the clerk as new entries are written.
How It Works — Step by Step
Step 1 / 5
  1. 1cat prints the entire file: fine for small files.
  2. 2less pages through large files without loading everything; search with /.
  3. 3head and tail show the beginning or end, e.g. a CSV header or the latest log lines.
  4. 4tail -f keeps following a growing log, the standard way to watch a running Spark or Hadoop job.
  5. 5wc counts lines, words and bytes; file and stat describe the file.

How do Linux file permissions work? Explain rwx and chmod (symbolic and octal).

Permissions & Users 8 min read Difficulty: Basic 6 of 40
Definition

Every file has permissions for three classes: owner (u), group (g), others (o), each with read (r=4), write (w=2), execute (x=1). ls -l shows them as e.g. -rwxr-x--- = 750.

For directories: r lists names, w creates/deletes/renames entries, x allows entering and accessing items. chmod changes them numerically (chmod 640 f) or symbolically (chmod u+x,g-w,o= f); -R applies recursively.

OctalSymbolicTypical use
644rw-r--r--normal files
600rw-------private keys, passwords
755rwxr-xr-xscripts, programs, directories
750rwxr-x---team-only scripts/directories
700rwx------private directories (~/.ssh)
chmod rwx octal permissions ls -l
Analogy
A shared office cupboard with three key sets: one for the owner, one for the department, one for visitors. Each key can allow looking inside (r), changing contents (w), or using the machine inside (x).
How It Works — Step by Step
Step 1 / 5
  1. 1The first character is the type: - file, d directory, l symbolic link.
  2. 2Then three triplets: owner, group, others, each with read, write, execute.
  3. 3Each triplet is an octal digit: r=4, w=2, x=1. rwxr-x--- is 750.
  4. 4For directories the bits mean: r = list names, w = create/delete entries, x = enter and access files.
  5. 5chmod sets them numerically or symbolically; root is not restricted by these checks.
Real-World Scenario
Exam papers on a shared server

Question papers are 640 (faculty group can read, students cannot); the results script is 750 so only the coordinators' group can run it; SSH private keys must be 600, or ssh refuses to use them.

Steps to Set Permissions
  1. Inspect
    ls -l or stat -c "%A %a %n".
  2. Decide per class
    What should owner, group, others be able to do?
  3. Apply
    chmod 640 file or chmod g+r,o-rwx file.
  4. Directories need x
    To enter or reach files inside: 750/755.
  5. Recursive with care
    chmod -R gives files and directories the same bits; use find -type d/-type f -exec chmod to treat them differently.
Cross Questions
Why could ls list the locked directory without x but not open a file in it?
r on a directory allows reading names; x is needed to access the entries (stat, open). Without x, ls prints names but cannot show details.
What does chmod 777 do and why avoid it?
Everyone can read, modify and execute; any user or compromised process can alter or replace the file. Use the minimum needed.
Can you delete a file you have no write permission on?
Yes, if you have w and x on its directory (deletion changes the directory, not the file), unless the sticky bit is set.

How do users, groups and ownership work? How do you change ownership?

Permissions & Users 7 min read Difficulty: Basic 7 of 40
Definition

Each user has a name, uid, primary group, home directory and login shell (/etc/passwd). Groups (/etc/group) let several users share access. Every file has one owner and one group.

Commands: id, groups, whoami; as root: useradd -m, passwd, usermod -aG group user, groupadd, userdel -r; chown user:group file (root only for changing the owner), chgrp group file (owner may change to a group they belong to).

useradd usermod groups chown chgrp /etc/passwd
Analogy
Users are employees, groups are departments. Every document is "owned by" one employee and "filed under" one department; the permission bits say what the owner, the department and everyone else may do with it.
How It Works — Step by Step
Step 1 / 5
  1. 1Every account has a username, a numeric uid, a home directory and a primary group.
  2. 2Users can belong to extra groups, which is how a team shares files.
  3. 3Each file is owned by one user and one group; permissions apply to owner, that group, and everyone else.
  4. 4Administrators create users and groups and change ownership; usermod -aG appends a group (without -a it replaces them).
  5. 5Account data lives in plain text files under /etc; password hashes are in /etc/shadow, readable only by root.
Real-World Scenario

Why does a new group not apply immediately?
Group membership is read at login; start a new session or use newgrp.

What is umask? How are default permissions decided?

Permissions & Users 6 min read Difficulty: Basic 8 of 40
Definition

New files start from 666 and new directories from 777; the umask lists the bits to remove. With the common umask 022: files 644, directories 755. 027 gives 640/750; 077 gives 600/700.

Check with umask (or umask -S symbolically); set for the session with umask 027, permanently in ~/.bashrc or system-wide profiles.

umask default permissions 022 027
Analogy

Definition

Definition

systemd is the init system (PID 1) on most distributions.   4. 4journalctl reads the systemd journal, filtered by unit and time, and can follow live.

How does SSH work? How do you set up key-based login and copy files with scp/rsync?

Archives, Remote Access & Environment 8 min read Difficulty: Advanced 32 of 40
Definition

SSH gives an encrypted remote shell (ssh user@host, port 22). Key-based authentication: ssh-keygen -t ed25519 creates a private key (~/.ssh/id_ed25519, keep secret, mode 600) and a public key (.pub); the public key goes into the server's ~/.ssh/authorized_keys (ssh-copy-id). ~/.ssh/config stores host aliases, users, ports and keys.

File transfer: scp file host:/path (simple copy), rsync -avz src/ host:/dst/ (incremental, resumable, can --delete). ssh -L local:host:port forwards ports (e.g. Jupyter, Spark UI).

ssh ssh-keygen authorized_keys scp rsync port forwarding
Analogy
Your private key is a personal seal that never leaves your pocket; the public key is a wax impression you give to the server. When you knock, the server asks you to stamp a fresh piece of wax and checks it matches.
How It Works — Step by Step
Step 1 / 5
  1. 1ssh-keygen creates a key pair: a private key that stays with you and a public key you can share.
  2. 2The public key is appended to authorized_keys on the server (ssh-copy-id does it).
  3. 3On login the server challenges, your client proves it holds the private key: no password travels.
  4. 4The same channel copies files (scp, rsync) and forwards ports for web UIs and notebooks.
  5. 5Strict permissions on ~/.ssh are required; leaked private keys must be replaced.
